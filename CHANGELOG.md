# Changelog

All notable changes to tern-kata are listed here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project uses [semantic versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- `m` on the Attention Page sends a message to the omp agent that raised the selected request. It reaches the agent at once, through an omp extension tern-kata loads into every omp agent it starts: a waiting or idle agent starts a turn on it, a working one gets it at its next step without its work being stopped, and a pending `ask` or tool approval stays until you answer it. Each omp agent has its own Agent address, `<actor>/<name>-<block id>`, set as its `KATA_INBOX_USER`, so no other agent reads its messages; only messages from you are delivered, and the agent's first message tells it to act only on those. The card asks before replacing a message the agent has not cleared, and says why when the agent cannot receive one (exited or not omp). When an agent exits, the Pane clears what is left at its address. Agents that load the extension run with `KATA_OMP_LIVE_INBOX=0`, so kata-omp leaves live delivery to it.
- `tern-kata worker status` names the installed binary's version when the running worker runs another one, and says how `tern-kata worker stop` moves it there.
- `/` on the Jobs, Runs and Workflows Pages searches their rows by a case-insensitive part of the row's text, as kata tui does. The search shows above the list, `esc` ends it, and an empty result says so.
- The Jobs Page inspector lists a job's next three runs with their time zone abbreviations, and says why there are none when the job is paused, its parent is closed, it only runs when started, or its runs can't be worked out.
- Issue list rows show the Date badge of an open Issue with a scheduled date or deadline, after the title, as kata tui does; a row that can't fit its whole title and the badge drops the badge.
- The Dates card and the Create card take kata's date-time forms, `YYYY-MM-DDTHH:MM[:SS]` and `YYYY-MM-DDTHH:MM:SSZ`; the preview shows the time.
- `N` on the Federation Page names a spoke: on the enrollment preview it sets the name the hub records with the enrollment, and on a spoke, in the list or its detail, it renames it on the hub, where an empty name clears it. The name shows on the spoke's card and detail. The card refuses a name that breaks kata's rule in kata's words before anything reaches the hub, and shows the hub's reason when it refuses a name another spoke holds.
- The Close card for a `done` close can cite one or more of the Issue's Attachments as evidence; the Events tab names a cited Attachment, and marks it `[removed]` once it is unlinked.
- `tern-kata migrate-attachments` moves the old attachments stored on this machine to Docbank, deletes the local copies, and lists the ones held on other machines.
- A `kata close` run by an omp agent the Pane started, or by a worker run whose profile `command` is omp, names that agent's omp session, so with `[close.transcript]` enabled in kata's config the close records the session and, with `agentsview_url`, a link to it in AgentsView. Worker runs now load tern-kata's omp extension for this, also under `--no-extensions`.

### Changed

- **Breaking:** tern-kata requires kata v0.21.0 or newer. kata v0.21 upgrades its database to schema 43 on first start, which older kata binaries cannot open; kata keeps a backup of the database from before the upgrade.
- The Pages are numbered as in kata tui: `1` Issues, `2` Jobs, `3` Runs, `4` Workflows, `5` Board and `6` Attention. `b` still toggles the Board and `T` still opens Attention.
- The Move card moves an Issue with its open descendants, as kata does. The preview names the Issues that move, the **Only this Issue** switch (`o`, or a click) moves the Issue alone, and the Notice says how many Issues moved. When kata refuses because of a descendant (archived, or held back for another reason), the card names it and keeps **Only this Issue** within reach; a subtree that changed during the move shows in words too.
- The Comments tab shows a discussion as a reply tree: replies nest under the comment they answer, four levels deep at most, a reply from another Issue is a line under its target, and confirm and refute show as tags, reading "(before edit)" when the evidence predates an edit of the comment.
- When an Issue's date changed elsewhere since the Dates card opened, the card writes none of your changes, refills that field with the current value and keeps your other edits, where it used to ask you to close and reopen it. A date that changes elsewhere during the save itself stops it there, and the card names the fields already saved.
- When the daemon doesn't know the Project a folder is bound to, the message names that Project, or the alias kata matched.
- The kata skill is written for kata v0.21: it starts, changes and stops a recurrence with `kata schedule --repeat`, moves an Issue with its open descendants, and closes with Docbank or attachment evidence.
- Switching to a stopped local daemon on the Daemons Page starts it through kata's client, with the Pane's own environment: `KATA_DSN`, `KATA_DB` and `KATA_SERVER` are no longer removed first. A switch to a remote entry still sends only that entry's own token.
- **Breaking:** Attachments are kata's own, with their bytes in Docbank: `@` uploads a file, the Attachments tab lists each with its media type and size, `enter` downloads it to a cache folder and opens it when it is an image, video, audio, PDF or text file (anything else is only saved, and the Pane says where), and `U` unlinks one (its bytes stay in Docbank). The daemon needs a `[docbank]` section in kata's `config.toml`; a daemon without one says so plainly in the Pane.
- **Breaking:** an Agent profile with no `extensions` key now runs omp with `--no-extensions`, where it used to load whatever omp discovers, so a worker run no longer loads omp's native extension modules, ambient hook files or installed plugins such as kata-plugin. Explicit `-e`, `--hook` and `--trusted-extension` paths in its `args`, skills, rules and MCP servers still apply. Add `extensions = "ambient"` under the profile to get the old behaviour back. A run already in progress when you upgrade uses the new default from its next attempt or step.
- `worker doctor` warns of kata-plugin's todo takeover only for an Agent profile that sets `extensions = "ambient"`.

### Removed

- `tern-kata attach` and `tern-kata detach`: use `kata docbank attachments add`, `ls`, `get` and `rm`.
- The `.kata-attachments` folder store and its pointer keys (`tern-kata.attachment.<name>`, and from 0.3 `attachment.<name>` holding `{host, path}`); `tern-kata migrate-attachments` moves what they hold.

### Fixed

- A cron expression whose `CRON_TZ=` or `TZ=` zone is quoted, such as `CRON_TZ="Europe/Berlin"`, is read with that zone: the worker no longer sets the job aside as naming another zone than its trigger's, and the Jobs Page shows its runs.
- Supervision no longer starts a second worker for `worker.lock` to refuse, all day long, after a plugin reload or a Tern update: the host half leaves the worker that is still running alone, logs one line naming it, and starts a worker within 10 seconds of its end.

## [0.7.2] - 2026-11-02

### Fixed

- **Update tern-kata** no longer reinstalls a window plugin that is already at the latest release, and no longer toasts that it was updated: it toasts "tern-kata plugin vX is up to date".
- The Issue detail's Owner, Priority, Labels and date badges no longer touch the badges in the rows above and below them, and a mono badge (a priority, a date, an Issue ref, also on Board cards) no longer has larger text than the badges beside it.

## [0.7.1] - 2026-11-02

### Fixed

- **Update tern-kata** updates the plugin on a Windows window machine after updating a session host on another machine. It used to fail in two ways. First, Windows could take over half a second to start the PowerShell when the script was on its command line, which ran the plugin step past Tern's time limit; the script now goes to PowerShell on its standard input, which starts in a few milliseconds. Second, the step ran inside the plugin's own folder, which Windows won't let the install replace ("tern-kata plugin was not updated"); it now runs in your home folder.
- On a Windows session host, a supervised Worker no longer stops `tern-kata update` and the install scripts from reinstalling the plugin while it runs: the plugin starts it in your home folder, not in the plugin's folder.

## [0.7.0] - 2026-11-02

### Added

- `tern-kata update` brings the session host to the latest release: it reads `version.txt`, downloads the OS archive and checks its SHA-256 against `checksums.txt`, then swaps the running binary (on Windows the old file is renamed to `.old`, and one still held by a running Pane or Worker is renamed aside, so nothing has to be closed first). It says when the binary is already up to date, never downgrades, refuses a build that is not a release with the command for its kind of install, refuses to run twice at once, and prints the new version, a reminder to reopen Panes and the skills update command; `--pause` waits for Enter after a success.
- `tern-kata update` also updates this machine's plugin (an installed copy whose `plugin.toml` version differs, through `tern plugin install --force`, also when the binary is already up to date; a linked copy or a missing `tern` is only noted) and restarts a supervised Worker when idle, by an idle stop the plugin answers with a fresh Worker. A Worker started by hand, or with `worker.manual`, is not stopped and is told to restart; after a forced refusal (a `worker.toml` one, or a pre-flight that could not check this machine) the Worker is left running, with the steps to fix `worker.toml` (`worker upgrade` or `worker edit`), then `worker stop`.
- The **Update tern-kata** palette command runs `tern-kata update --pause` in a Pane on the focused Pane's machine and, when that machine is not the window's and the update succeeded, reinstalls the window machine's plugin from the same release without a terminal, then toasts "tern-kata plugin updated to vX" (or the script's last error line). The startup failure toasts and the worker log now say tern-kata may be older than the plugin and name Update tern-kata or `tern-kata update`.
- `tern-kata update` runs the downloaded binary's pre-flight check before swapping and refuses a release that this machine's kata daemon or `worker.toml` can't run (naming the versions or the config error), unless `--force`, which prints the refusals as warnings; a kata daemon that does not answer within 10 seconds is only a warning.
- The window plugin checks for a new release once a day (at window start and every 24 hours while the window stays open) and toasts once per version when one is out, naming Update tern-kata; the **Turn tern-kata update checks off/on** palette command or `TERN_KATA_NO_UPDATE_CHECK` turns the check off, and a plugin linked with `tern plugin link` never checks.
- The window plugin is installed from the release, next to the binary, not from the `main` branch on GitHub, and window machines get a plugin-only one-liner: `TERN_KATA_PLUGIN_ONLY=1` makes `install.sh` and `install.ps1` install just the plugin (no binary, `PATH` or skills step), fail when `tern` is not on `PATH`, and leave a linked copy as it is.
- The worker reference explains how to back up and restore the worker's local state: what to copy, what to leave out, and what a restore on another machine means.
- Saved views: a name for a base fixed Collection or Project with the Filter card's fields and a search text, kept in `views.toml` beside `filters.toml`. The Menu's Views level lists them by name after the fixed Collections and ends with **New view**, which opens the View card; opening one makes its base current with its filters applied (`@me` is the Pane's actor) and the filter line ends with "view <name>" while the Collection and filters are still the view's. `f2` edits the view under the cursor, `ctrl+d` deletes it after "Delete view <name>? y/n", and a view whose Project is gone or archived says so. `tern-kata views` lists the fixed Collections and saved views, `views show <name>` prints the Issues as the Pane groups them (`--json` for one object per group, `@me` from `--as`), and `views add <name>` and `views rm <name>` save and delete a view, all without Tern and with the View card's checks and messages. See [Pages and the Board](docs/guide/pages-and-board.md#saved-views) and [Views from a shell](docs/guide/views.md).
- `w` on an Issue opens the **Agent card**, with or without agents: it lists them with state, start time and where each is, `enter` goes to one, `b` sends one to the background, and `s`, `t` and `g` start a new interactive omp agent in the Issue's checkout, in a split right of the kata Pane, a tab (right of the kata Pane's tab, in that Pane's Tern session, with the plugin's window half) or the background. `agent.toml` sets the actor, command and agent name for every Project or one, and a closed Issue refuses `w` with a Notice. The agent runs through `tern-kata agent` (the `tern-kata` on the PATH of Tern's shell, so it must be this version) with its Issue as `KATA_REF`, so kata-plugin's todo plan hangs under that Issue, and without your `KATA_INBOX_USER`; it renews its claim when it already owns the Issue, finishes or drops its todo children before closing, and when it stops without closing it comments why, sets the Issue's **Work attention** to `needs-human` with its reason and labels it ready-for-human.
- The **Agent badge** on an Issue's list row, Lane row, Board card and detail shows "agent working", "agent waiting for you", "agent idle" or "agent exited", with " · N" when the Issue has several agents; on the Board card and in the detail a click focuses the agent.
- A **Background agent** opens beside the Pane when you click its Agent badge in any kata Pane or focus it in the hidden "kata agents" session, as Tern's notification for an agent waiting for you does, and the Pane that started it moves it back into the hidden "kata agents" session when it works again after waiting for you, wherever it was opened.
- A **Background agent** ends once its Issue is closed and it is idle or has exited: the Pane that started it closes its block with `tern close` and drops its entry and prompt file, unless you have it open in any kata Pane; a close that fails shows Tern's words in a Notice and leaves the entry. An agent in a split or tab is closed this way only once a kata Pane has sent it to the background.
- While an agent you started waits for you, the Issue holds an **Attention request** for your Inbox address with the agent's last message, also when the Pane finds the agent already waiting; it clears when no agent on the Issue waits and when the Pane quits, and a newer request someone else wrote stays. The request names the agent's `agent.toml` name (by default its program, such as `omp`) as its teammate, so the Attention Page shows `actor/<name>`; an Issue holds one request for you, so the agent that waited last is the one named. An agent that exits while its Issue is still open, also when you quit it with `/exit`, leaves the request "agent exited without closing <ref>" until the Issue closes, another agent on it waits or the Pane quits.
- A kata Pane's icon in Tern's tab bar is kata's mark, the katakana カ, in place of the terminal icon, tinted like the icons beside it, also in a window attached to the Pane's host from another machine.
- A Project can share its Lane list through kata: **Save to: The Project** on the Lanes card writes it to the Project's `tern.lanes` metadata, every tern-kata on the daemon shows it before its own `lanes.toml`, and a change from another machine reaches an open Board at once. The Board and the Lanes card say whether the list in use is shared, this machine's or the default; `ctrl+x` on the card stops sharing, and a Project changed since the card opened keeps your text and names the list it shares now. An archived Project's Board shows its shared list, which the card can't change until the Project is restored.
- Date fields in the Dates, Create and Recurrence cards open a calendar beside the field on `ctrl+d`: the arrows move it by a day or a week, `enter` or a click picks the day and `esc` closes it unchanged. Typed dates, `today`, `tomorrow`, `+Nd` and `+Nw` work as before, and the card's other date is marked on the calendar.
- A right-click on an Issue row, a Lane row or a Board card opens a menu of Open, Agent…, Close, Priority…, Dates… and Move to Project, plus Reopen on a closed Issue, each showing its key and doing what that key does on that Issue. On a closed Issue, Close and Agent… are disabled and say why, and `x` says the Issue is already closed instead of opening the Close card.
- Hovering an Issue reference (the Relationships line, Comment links, Links and Events rows, the detail's parent and the Blocked marker) shows a card with its ref, title, status, owner with the claim's expiry and updated time; a Children row's ticket shows the same facts as a tooltip. A reference that isn't loaded shows only what its link carries.
- An open Issue's **Work attention** (`work.attention` set to `needs-human` or `stuck`, by an agent, kata-plugin or anyone else) shows as "needs human" or "stuck" beside the Agent badge on list and Lane rows and as a badge on the Board card, and with its message as a Work attention property in the Issue detail.
- A worker profile's `extensions` key (`"ambient"`, the default, `"none"` or a list of absolute paths) chooses which omp extensions its runs load, and `worker doctor` warns when kata-plugin's omp extension is installed and a profile still loads ambient extensions, which gives its headless runs kata-plugin's todo takeover.
- When a run succeeds but leaves its per-run Issue open, the worker also sends the Issue's owner (else its author) an **Attention request** naming the Issue, beside the comment and the `needs-review` label.

### Changed

- A workflow's prompt step no longer inherits kata-plugin's steering variables (`KATA_REF`, `KATA_TEAMMATE`, `KATA_INBOX_USER` and the rest) from the worker's environment: of kata's variables it keeps only those that reach and sign in to the daemon.
- New kata Panes on Windows no longer wait for the PowerShell profile: the kata Pane, Update tern-kata and Install tern-kata's Windows choice start PowerShell with `-NoProfile`, while your own shells and other Panes still load it.
- The filter line under the top bar shows each active filter as a chip after a funnel ("status open", "owner me", a Relationship in the Filter card's words such as "relationship has parent"), and the muted note "default" or "view <name>" at its end, in place of the plain `status=open (default)` text.
- The help sheet (`?`) lists the global keys and the keys of the Page it is opened over, each group of keys as a card, set in one to three equal-width columns as the Pane allows and balanced so the columns end close together; the keys are in an accent mono column that lines up down each column, a long action wraps inside its card, the agent key `w` sits on one short line, and the last line names both keys that close the sheet: "press ? or esc to return".
- A cron trigger whose expression names a `CRON_TZ=` or `TZ=` zone other than the trigger's `timezone` no longer runs in the expression's zone: the worker sets the job aside with "its cron expression names zone X but the trigger's timezone is Y", shown by `worker status`, `worker doctor` and the Job card.
- A job can name its adapter in `options.adapter`: the Job card has an **Adapter** field and puts `tern-kata` on new adapter jobs, and the worker neither schedules nor runs a job that names another adapter, listing it in `worker status`, `worker doctor` and the Jobs Page with that reason; `worker upgrade` grants such a job no secrets or command steps. A job without the key runs as before.
- The Menu's top level is short: the bound Project, **Views**, **Projects**, the Lettered Pages, Restore a deleted Issue and New Project. The fixed Collections (Inbox, Today, Upcoming, Deadlines, All Open, Logbook) moved into a **Views** level, which Back, `esc` or `backspace` leave for the top with the cursor on Views. The Views row names the current fixed Collection or saved view, typing still finds every Collection from the top, and an unbound directory's Menu sidebar shows the Views level.
- **Open kata**, `F9` and kata links no longer fall back to a new tab when Tern can't split the focused Pane: the Tern that tern-kata now needs lets plugins split and find a remote host's Pane.
- `install.ps1` says that new Tern tabs and Panes see the `PATH` it changed at once; only shells already open and other programs already running need restarting.
- The Issue detail's creation line no longer says "creation: legacy", which every Issue and comment on a Project without federation carries. A legacy Issue or comment shows "source: <actor> / <teammate>" only when it has a teammate or was created by someone other than its author, and no line otherwise; verified and pending lines are unchanged.
- The Worker card lists its facts (Project, Checkout, `worker.toml`, Worker, Supervision) as an aligned grid, each value leading with its state in that state's colour, and names the checkouts `worker.toml` maps only when they differ from the Checkout row.
- The Worker card's restart and supervision-off questions list **when idle** and **now** each beside what it does to the runs in flight, and no longer say a run is held `interrupted` when none is in flight.
- `e` on the Worker card, `ctrl+e` in the Draft editor and the Workflow card, and `tern-kata worker edit` open `$VISUAL`, else `$EDITOR`, else `vi`, as kata's own TUI does.
- A Project's `capacity` defaults to 3, so one hung run no longer holds its only slot until its timeout. `worker init`, `worker add` and the Worker card's Set up and Serve this Project write `capacity = 3`; a `worker.toml` that says `capacity = 1` keeps it, and one with no `capacity` line gets 3 after the upgrade. Every run's contract now tells the agent that other runs may be working in its checkout, and to make a git worktree when it needs a tree of its own.
- Inbox, Upcoming and Deadlines read kata's all-open snapshot and pick their Issues in the Pane, as kata's web does, instead of the daemon's inbox, upcoming and deadlines views that kata keeps only for older web UIs. They list the same Issues in the same groups; a Deadlines row's start date now reads in the Pane's time zone, as it does in every other Collection.
- A held run's summary in kata starts with the line `reason: <code>` and has the detail on the next, kata's convention for a machine-readable cause, instead of `<code>: <detail>` on one line. The Runs Page shows `reason: <code>` on the card and a Reason line in the detail for any run whose summary leads with one, another executor's too, and for runs held by an earlier tern-kata; the Jobs Page and a Workflow's inspector word such a run as `<code>: <detail>`.
- tern-kata needs Tern 0.9.9 or newer, which draws the buttons, tables, selects, calendars, menus and empty states the Pane now uses.
- The Pane is drawn in Tern's interface face (sans): Issue refs, dates, counts and times stay in mono, the key line at the bottom is a key legend, and the Issue detail's properties line up in either face.
- Popup card and Menu buttons are Tern's own buttons, with their keys drawn as keycaps. A card's buttons sit in a footer bar that stays in view while a tall card scrolls, its head names the card with its subject (the Issue, Collection, view or workflow) as muted text after it, a destructive confirm is red, and a button whose action can't run now, such as Go to agent with no agent on the Issue, is disabled with the reason as its tooltip.
- Choice fields in Popup cards are Tern's controls: a yes/no field such as Worker Trust is a switch, a short choice such as the Filter card's Status is segmented tabs, and the others are selects (`down` opens one, typing searches a long list, `enter` picks). `left`, `right` and `space` still step a choice, a click picks, and Recurrence weekdays are unchanged.
- The Issue detail's Children is a table that sizes its columns and drops the least important ones when narrow; a click on a row still goes to that child.
- Empty Pages and lists (Attention, Runs, Jobs, Workflows, an Issue list with no Issues and the detail with nothing selected) say what is missing and what to do, with a button when one key fills them, and a Lane with no cards says so. Words that wait on someone use Tern's pending colour.
- Tern closes a kata Pane without asking only when kata's `[tui] confirm_quit = false`, as it stands when the Pane starts; with the default it still asks.
- Supervision is decided by tern-kata itself: the window plugin's host half asks `tern-kata worker supervised` whether to start the worker, so update tern-kata and the window plugin together. A tern-kata too old to answer leaves the worker unstarted, and the plugin logs this once per daemon with the advice to update.
- `tern-kata views` words dates (`scheduled X · due Y`) and the filter summary (`status=open · owner=dana · search=x`) the way the Pane does.
- The Issue detail with many comments, the Issue list and the Board draw faster, a run's detail reads its output tail in bounded memory, and the worker no longer lists every Cron job on each Issue event while an occurrence waits nor reads every run journal to admit a job that forbids overlap.

### Fixed

- The **Attention request** of an omp agent waiting for you says what it waits on: the question of its pending ask call, else its last message, no longer the cut-off start of a thinking block ("Thinking…\nI'm checking who owns the claim on"); an omp agent with no text to show gets "agent waiting for you", and an agent that is not omp keeps its last message.
- An agent started from a Pane on another daemon (by `KATA_HOME`, by `KATA_SERVER` or after a switch on the Daemons Page) runs its `kata` commands against the Pane's daemon, so its `KATA_REF` Issue is claimed, commented on and closed there and kata-plugin registers nothing on Tern's default daemon. The Pane's token, the `token_env` values its `config.toml` names (each reaches only the daemon kata scopes it to) and a Postgres DSN reach the agent through private files, never the command line, and the block's own `KATA_DB`, `KATA_DSN` and `KATA_POSTGRES_SCHEMA` no longer mix with the Pane's home. A switch to a local daemon that the checkout's `.kata.local.toml` pin or `active_daemon` would override, or to a remote entry without a token while `config.toml` has an `[auth]` credential, is refused with the reason in the "Cannot start an agent" Notice. A Pane on the default daemon starts agents as before.
- `worker doctor` no longer tells you to create `worker.toml` when the file exists but does not load, and after a warning it says nothing is missing and how many warnings it printed.
- `install.ps1` works in Windows PowerShell 5.1, the `powershell` the README one-liner and the palette's Install and Update commands run: it no longer stops with "You cannot call a method on a null-valued expression" before downloading anything.
- `install.ps1` no longer fails with "Cannot create a file when that file already exists" when the previous install's `tern-kata.exe.old` is still held by a running tern-kata: reinstalling on Windows works while an older tern-kata still runs, and the next run removes the leftover `tern-kata.exe.old-*` files once those processes have exited.
- A notify job with a zero lead, the current-owner-or-author recipient and an Issue-date trigger is skipped by the worker only when it notifies the trigger's own Issue; one that names another Issue to notify is now sent by the worker to that Issue's owner or author.
- An `execute` job on an existing Issue no longer starts while the Issue is `someday` or scheduled for later: the scheduled occurrence waits without taking a slot until the Issue is ready, past its catchup grace and across worker restarts (the 7-day catchup window still applies), `worker status` says why, and a manual run is refused with the reason; `deadline_on` never defers it.
- `e` on the Worker card and `ctrl+e` no longer only blink when neither `$VISUAL` nor `$EDITOR` is set, as in a Pane started by **Open kata**: they open `vi`, and with no `vi` either the card says to set one without leaving the Pane.
- Popup cards draw their error, pending, warning and success lines in the theme's colours instead of the plain text colour, as do the worker notes of a Workflow's inspector.
- With Tern 0.9.8 on a high-density display, the Issue list, the detail and the other column lists no longer run past the bottom of the Pane and scroll the top bar away: each list now fills its column and scrolls inside it at any display scale or Pane height.
- Re-enabling a disabled Cron job runs nothing for the time it was off, whatever its `catchup`, with or without a worker restart in between.
- A succeeded run whose per-run Issue can't be read when the worker reports it sends its final observation and waits to comment and label until the Issue can be read, so a closed Issue no longer gets the final message comment and `needs-review`.
- During an idle stop, `worker abandon` of a Held run is accepted; `run` and `resume` are still refused while the worker stops.
- `worker resume` of a Held run whose output can't be set aside, for example because another program has it open on Windows, is refused with the reason and the run stays held as it was, instead of the new attempt overwriting that output.
- A finished turn whose `agent_end` line passes 64 MiB is recognised, live and on recovery (`no_receipt`, not `interrupted`), while a non-terminal one still is not; a single write over the line limit that contains a newline is checked too.
- Stopping a Recurrence from its card or with `tern-kata recur --stop` writes nothing when its rule, start date or time zone changed since you read it and shows the schedule as it stands; a stop that got no answer says the Recurrence may have been stopped.
- Agent mapping (`agents.json`) changes from two Panes at once no longer lose one, and neither do Lane list (`lanes.toml`) and Default filter (`filters.toml`) saves: a save applies on top of another Pane's save, or is refused with the reason shown on the card.
- Sending an agent back records it as a background agent even when a later move step fails, and the Notice still shows Tern's error.
- A Lane list answer sent before a save no longer replaces the saved Lanes, and saving the Lane list to the Project keeps the Undo history.
- Undoing a body edit after someone else changed the body writes nothing and says why, and undoing a label add or remove that someone else already changed says so; a change to another field no longer blocks either.
- A Pane reading live agent blocks waits only until its own deadline instead of behind another read's `tern ls`.
- `ctrl+u` on an empty Popup card field keeps the card's error.

## [0.5.0] - 2026-10-25

### Added

- `tern-kata completion bash|zsh|fish` prints a shell completion script for the subcommands, the worker forms and their flags: `source <(tern-kata completion bash)` (or `zsh`), or `tern-kata completion fish | source`.
- `tern-kata worker status --json` prints the worker's status as JSON for scripts, in the shape the worker's control socket answers it.
- `tern-kata worker upgrade` gives the jobs you have today what they had before secrets and command steps became per-Project: for each `[[projects]]` table without `secrets` or `commands`, it adds the secrets its jobs use and `commands = true` when one of its workflows runs a command step, leaving every other line as it was. A key you already wrote stays; what the jobs need beyond it is printed. `worker doctor` suggests it when a job is set aside for either reason.

### Changed

- A command line tern-kata refuses exits 2, as Unix tools do: a subcommand's usage error (a missing ref, an unknown flag) no longer exits 1, and the Pane's own refusals no longer exit 3. A subcommand that fails while running still exits 1.
- Inside Tern, `tern-kata` refuses arguments only `kata tui` takes, naming them, instead of opening the Pane as if they weren't there; outside Tern they still go to `kata tui`.
- Ctrl+c, a terminate or a hangup stops a subcommand cleanly and it exits 128 plus the signal's number (130 for ctrl+c); a second one ends it at once. A terminate or hangup closes the Pane cleanly, and the foreground worker stops on a hangup as on ctrl+c.
- After a lone `--`, `--help` and `--version` are names, not flags, so `tern-kata attach <ref> -- --help` attaches a file called `--help`.
- The Pane responds faster in large Projects. Moving the selection in the list, the Issue detail or the Board reuses the rows already worked out instead of rebuilding them on every key, and a live refresh builds them once. The Jobs Page counts each cron job's "about N Issues a day" warning once per job revision when the jobs are read, instead of on every key, which kept it slow with a job that fires every minute. The Collection and Issue detail reads from a local daemon over its Unix socket now arrive uncompressed, so neither the daemon nor the Pane spends time on gzip for each refresh.
- A worker serving several Projects keeps each one's secrets to itself: a Project's jobs may use only the `[secrets]` names its `[[projects]]` table lists in `secrets = [...]`, and an empty or missing list allows none. A job naming an unlisted secret is set aside, and is held `secret_unavailable` if run anyway. Run `tern-kata worker upgrade` once to list the secrets your jobs use today.
- Workflow command steps (`sh -c`) run only for a Project with `commands = true` in `worker.toml`; without it, a job whose workflow has a command step is set aside with that reason. `tern-kata worker upgrade` adds the switch where a workflow needs it.
- The worker writes an Issue's title into the agent's prompt as one line, so a title with line breaks cannot pass for another section of the prompt.
- The worker's control socket answers only its own user: the socket is mode 0600, the state folder (followed through a symlink) is narrowed to 0700 when open to others and refused when it is someone else's, and on Linux and macOS a connection from another user is closed. A run or Project uid that is not a ULID is refused before it names a file.
- Attaching and detaching refuse an Issue uid from kata that is not a ULID, so a daemon's answer cannot point the Attachment store outside its folder.
- The live event stream fails, and reconnects, on a line or an event over 1 MiB, instead of holding however much a daemon sends.
- Subcommands and the foreground worker show control characters in text from kata (titles, attachment names, a daemon's error message) as `�`, so an escape sequence in it cannot reach the terminal.
- Leaving a federated Project sends the hub's token over plain HTTP only when your own catalog entry for the hub sets `allow_insecure`; the binding's flag, which the spoke's daemon reports, no longer counts.

- The worker runs workflow jobs: an `execute` job whose action names a workflow runs its steps one at a time in dependency order, a prompt step as one fresh headless omp process like a prompt job and a command step through `sh -c` in the job's checkout as the worker's user (output kept as its first 1 MiB and last 256 KiB), each retried up to its `retries` after a certain failure. kata records one run for the workflow with every step's result in its summary, a step that fails after its retries fails the run and skips the steps that depend on it, and a timeout is shared by all steps. The journal covers steps, so a crash mid-workflow holds the run at the uncertain step and `tern-kata worker resume` continues from it (a held command step runs its command again); `run-detail` lists every step. Workflows with `options.on_fail` loops, `on_failure: "park"`, a mismatched profile or more prompts than `max_run_prompts` are refused with the reason.
- A run whose output log cannot be written or opened settles as its process ended, and `worker status` and the run detail say "output not recorded" with the reason.
- Reopening a parent (`r`), resuming a recurring-child job (`p`) and restoring one (`x` on an archived job) first open the Backfill card when the job's catch-up is every missed run and runs were missed: it counts the child Issues that kata's daemon would create at once, job by job, and offers to create them, to switch the job to `latest` and go on (a Guarded write of the catch-up before the reopen, resume or restore), or to cancel and change nothing. Nothing is asked when nothing was missed, the job catches up with `latest` or `skip`, or it would stay paused anyway.
- The worker fires `issue-scheduled` and `issue-deadline` jobs on the Issue's own planning date, read from kata as an instant (the Issue's time zone, else the recurrence's, else the daemon default, else UTC), a deadline `lead_seconds` earlier. A job fires once per date value; when the Issue's date changes the worker follows its events and waits for the new instant instead, and a date set or moved into the past after the job was first seen (also after it was cleared) is treated like any missed occurrence under the job's `catchup`. An `execute` job on an Issue date runs its prompt as any prompt job does. The worker also delivers adapter `notify` jobs on an existing Issue, on any trigger: it puts the inbox request with the job's message (the Issue's id and title when blank) in the recipient's inbox, resolving `current-owner-or-author` from the Issue when it sends, and records a succeeded or failed run with no agent started. A zero-lead `current-owner-or-author` notification on an Issue date stays with kata's own date sweeper.
- The worker runs agent prompt jobs on their schedule: a `cron` trigger (five fields or descriptors such as `@daily`, in the trigger's time zone, read by kata's own parser), an `interval` or `@every` one (counted from the job's creation) and a `once` instant fire without a request, while `manual` jobs still run only on `tern-kata run`. `overlap: forbid` holds a job's next occurrences until its earlier run has settled, `allow` starts them as slots free, and occurrences beyond the Project's capacity queue and start oldest first (`worker status` shows the next run and the queue). After downtime or a pause, `catchup` `all` runs every missed occurrence in order, `latest` only the newest, and `skip` only the newest within `grace_seconds`; at most 7 days and 100 occurrences are kept per job, and the oldest overflow is dropped and logged. A run over `timeout_seconds` is stopped and failed with "timed out". Editing, disabling or re-enabling a job in kata changes its schedule within about a second, without restarting the worker, and a changed definition drops the occurrences still waiting. A per-run Issue gets its `scheduled_offset_seconds` and `deadline_offset_seconds` as its Scheduled and Deadline dates, counted from the occurrence.
- `tern-kata worker` runs kata's agent prompt jobs on your machine with no Tern window open: from `worker.toml` (executor label, served Projects with capacity, checkouts, Agent profiles, secret sources, limits) it runs each job's prompt through headless `omp` in the job's checkout, creates the run's Issue (or comments on the job's existing one), and records the run in kata as running, then succeeded or failed with the agent's final message and token counts. The agent is told its Issue and to comment and close it with evidence; an Issue left open gets the final message as a comment and the `needs-review` label. A run over its timeout is stopped and failed. Native jobs and Projects not listed in `worker.toml` never run, a second worker on the machine is refused, and a Project whose lease another worker holds admits nothing. A run whose agent may have started when the worker stopped is held as unknown, never sent again. Anyone who can write jobs in a listed Project can run prompts and commands on your machine; see the README.
- A worker that is stopped or killed and started again on the same state folder never sends a run's prompt twice: each run's journal is saved before every step, and a run whose agent may have started and whose outcome the worker cannot prove becomes a Held run, recorded `unknown` in kata with the reason first in its summary and a comment on its Issue (`launch_unproven`, `interrupted`, `no_receipt`, `group_unproven`, `agent_login`, `agent_quota`, and the nothing-started reasons), with its job's overlap gate closed until you settle it. `tern-kata worker resume <run-uid>` continues it as a new headless omp attempt on the saved session with a prompt that warns the previous turn may have partly run, and the run goes back to running; `tern-kata worker abandon <run-uid>` records it `cancelled` ("abandoned by <actor>") and frees its slot. `worker status` lists each held run with its reason and the commands that settle it, and the worker's control socket answers a run's detail (steps, session, output tail) and resume and abandon requests for a later Pane.
- The tern-kata plugin gains a host half (`host.luau`) that keeps the worker running with no Tern window open: when `worker.toml` exists it starts `tern-kata worker` in Tern's session daemon and starts it again whenever it exits, waiting 1 second, then 2, 4 and so on up to a minute, and again whenever the daemon starts. ### Changed

- tern-kata requires the kata v0.20.0 daemon, for the Pane and the Worker alike: kata v0.20 says cron peers must upgrade together and does not support v0.19 beside it. Against an older daemon the Pane refuses to connect and says to upgrade, and the Worker and `worker doctor` name v0.20.0.
- Attaching a file moves from `u` to `@` in the list, on the Board, in the Lane view and in the Issue detail, because `u` undoes now; `U` still lists and removes Attachments. An Issue with no Attachments says "No attachments, @ to attach".
- An explicitly empty `--as` (`--as=` or `--as ""`) is refused with "--as must be non-empty" for the Pane launch, `attach`, `detach`, `recur`, `run`, `worker resume` and `worker abandon`, where it used to act as the fallback actor. Without `--as` the actor is still `$KATA_AUTHOR`, `$USER`, git `user.name`, then "anonymous", and an empty variable still counts as unset; `worker init --actor` is unchanged.
- tern-kata builds against kata v0.20.0 and its lean Go client, so the release binary is about 27 MB instead of about 38 MB and its download about 13 MB instead of about 19 MB.
- The top bar names a local or remote daemon without `kata` on `PATH`: the kind comes from kata's own discovery, and connecting starts no `kata` process.
- `worker status` reasons for a Workflow that breaks kata's own rules (version, step keys, retries, `after`, step shape, options) now use the Workflow card's wording, and the worker also applies the step-key and options rules (no credentials or local paths) to the Workflow it reads.
- Field filters (project, status, owner, label, relationship) now keep the Collection's grouping and headings, so Today with a status filter still shows Overdue and Today; only a text search shows the flat Results list.
- An Attachment pointer is now the `tern-kata.attachment.<name>` meta key, because kata's native attachments claim `attachment.<id>`; tern-kata moves pointers written under `attachment.<name>` by itself, once per Project and kata daemon on each machine, when a Pane for the Project starts or `tern-kata attach` or `detach` runs, and leaves kata's own `attachment.*` keys and the files alone.
- The Issue detail's heading is the bare `#id` in a Project Collection, since the top bar names the Project; it names the Project, `project#id`, only in Collections that span Projects (Inbox, Today, All Open and the others).
- Following a ticket of another Project from a Project Collection switches the Pane to that Project instead of opening the ticket as a stranger in the current one: the Pane keeps its Page and selects the ticket, the top bar reads "Project: <that Project>", and Esc goes back through the jump history to the earlier Collection, Page, Lane view, selection and focus, one step per hop. This covers an id on a Board card's Relationships line, the detail's Links and children rows, `^`, and a `kata://` or `https://kata.invalid/` link; following inside a Project and from Collections that span Projects works as before.
- The top bar's title ("Project: tern-kata", or the Collection's name) keeps the accent colour whichever column has focus, so following a link into the detail no longer dims it; the columns' borders show focus.

## [0.3.0] - 2026-10-20

### Added

- `tern-kata recur <ref>` prints an Issue's schedule in words with the next Occurrence's date; with `--frequency daily|weekly|monthly|yearly` (and `--every`, `--on`, `--day`, `--month`, `--until` or `--count`, `--start`, `--zone`) or `--rule <rrule>` it makes the Issue recur or changes its schedule, and `--stop` stops it, from a shell or an agent without Tern. The flags go through the Recurrence card's own checks, so invalid input is refused with the card's messages and nothing is sent; a schedule changed meanwhile is printed, not overwritten. Refs, `--as`, the Binding rule and exit codes match `attach`. The kata and tern-kata skills now tell agents to use it.
- `tern-kata attach <ref> <file>...` and `tern-kata detach <ref> <name>` attach files to an Issue and remove them again from a shell or an agent, without Tern. `attach` prints each stored absolute path; both need the directory to be bound to the Issue's Project and exit 1 on any failure.
- An Attachment is a copy of the file in `.kata-attachments` at the root of the Project's primary checkout, which every linked worktree shares and which stays out of git; an empty `.gitignore` there is rewritten with `*` on the next attach. An `attachment.<name>` meta key on the Issue holds the copy's host and path. Detach clears the key, including one with an unreadable value, and deletes the copy only when it is on this machine and in that Issue's folder, saying what became of the file. A detach clears the key only while it still holds what was read: a pointer rewritten meanwhile survives with its file, and the refusal says the Attachment changed. When the key is cleared but the copy can't be deleted, `U` closes the form and `tern-kata detach` prints "Removed <name>; could not delete <path>: <reason>" on stdout, then exits 1 with the error on stderr.
- The Issue detail has an Attachments tab after Links. It lists the Issue's Attachments by name, each on its own row whatever the name; a file held on this machine is a link to the file (one on a Windows network share links as `file://server/share/...`), one held elsewhere reads "<name> on <host>", and an Issue with none says "No attachments, u to attach".
- `u` on the selected Issue, in the list or the Issue detail, asks for a file's path and attaches it. `U` lists the Issue's Attachments by name and removes the one chosen, and says so instead of opening a picker when there are none. Both keys explain why when the directory is not bound to the Issue's Project. Attaching is refused when this machine's host name can't be read, and a pointer with an empty host is never treated as on this machine. The footer and help sheet list them beside the label keys. A successful `u` shows "Attached <stored name> to <short id>", so a file stored as `shot-2.png` is named.
- Two agent skills ship with tern-kata: `kata` for working with the kata CLI and `tern-kata` for reading and attaching Attachments. `npx skills add Dangerboi/tern-kata -g` installs them (`bunx` works too), and the install scripts offer to run it when they run in a terminal, with `bunx` when Node.js is missing.

- The children table has an owner column, a header row and alternating shading.

### Changed

- The Issue list draws each id in its Lane's Board colour (Done's for a closed Issue) and each owner in the user colour, as the Board does; where a list span has no such colour it takes the nearest text colour. A Project's Lane list now loads when the Project opens, not only when the Board turns on.
- The Issue detail uses the Board's colours: the heading's `#id` takes the Issue's Lane tone (Done's for a closed Issue), the owner is a user badge, labels are info badges, and Scheduled and Deadline are badges toned by their own date under the Date badge rules (muted on a closed Issue or before the Pane calendar's date is known).
- tern-kata requires the kata v0.19.0 daemon. Against an older daemon the Pane refuses to connect and says to upgrade.
- Saving a Draft and posting a comment or reply conflict only when the Issue's text changed. An agent claiming the Issue, a claim expiring or an owner change no longer causes a conflict. Closing succeeds while the Issue is open, and if someone closed it first the Close card says so.
- The Pane finds the daemon the way the kata CLI does, so it works without `kata` on `PATH`. Connecting gives up after 10 seconds instead of hanging.
- A workspace bound to a Project the daemon does not know says to run `kata init`, for local and remote daemons alike. Only an unbound workspace opens the Inbox.
- The Logbook, Today, Overdue, Upcoming and Deadlines groups, detail times and the Recurrence card's Start date use your local time zone.
- Child counts arrive with the Collection, so a live refresh downloads nothing extra and a failed count no longer discards a Collection that loaded.
- The footer shows each place's hints in kata tui's order and words and wraps them into a grid instead of hiding the ones that do not fit. The Issue detail footer adds label, owner, parent and priority hints.
- Going back after a jump returns to the tab and row you left.
- Compact activity lists the oldest entry first.
- A kata link opened in Tern reuses a kata Pane only in the current tab.
- Every card button names its keys, for example "Keep editing (n / esc)", including the Filter card's Apply and Cancel.
- Comments, replies, new Issues and closes can be sent again safely after a lost answer, without duplicating. A Recurrence change that keeps losing a race to another edit says so in plain words.

### Fixed

- Today and the other date groups move to the new day at local midnight, also when the machine slept through it.
- Text written in `$EDITOR` is kept in a file, and its path is printed, when Tern cannot be reached after the editor closes.
- `--as` and `--issue` refuse a value that is another flag, so `--as --issue x` no longer starts tern-kata as the actor `--issue`.
- `install.ps1` parses, keeps `%VAR%` entries in `PATH` and says when it changes `PATH`, so programs started from Explorer, such as Tern, see it.
- **Open kata**, `F9` and kata links open tern-kata in a new tab, in the focused Pane's directory, when Tern can't split the focused Pane, instead of doing nothing.
