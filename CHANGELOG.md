# Changelog

All notable changes to tern-kata are listed here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project uses [semantic versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- The Pane shows this machine's worker. The Jobs Page says whether it runs and serves the Project (no worker, not served, admitting nothing and why, or its slots in use), and `R` asks it to run the selected adapter job now under the usual lease, overlap and capacity rules, refusing with the reason on a recurring-child job, an archived job, without a worker or for a Project it does not serve. On the Runs Page a run of this machine's worker shows its local state: a `held` badge with the reason on its card, and in its detail why it is held and whether `u` would work, its steps, the tail of the agent's output and its omp session. While a run runs the page follows it every 2 seconds. `o` opens a finished or held run's omp session in a new Tern tab (`tern new tab --cwd <checkout> -- omp --resume <session> --session-dir <folder>`), `u` resumes and `A` abandons a held run through the worker's control socket, with refusals shown; runs of other executors show what kata holds. The help sheet lists the keys.
- Reopening a parent (`r`), resuming a recurring-child job (`p`) and restoring one (`x` on an archived job) first open the Backfill card when the job's catch-up is every missed run and runs were missed: it counts the child Issues that kata's daemon would create at once, job by job, and offers to create them, to switch the job to `latest` and go on (a Guarded write of the catch-up before the reopen, resume or restore), or to cancel and change nothing. Nothing is asked when nothing was missed, the job catches up with `latest` or `skip`, or it would stay paused anyway.
- The worker fires `issue-scheduled` and `issue-deadline` jobs on the Issue's own planning date, read from kata as an instant (the Issue's time zone, else the recurrence's, else the daemon default, else UTC), a deadline `lead_seconds` earlier. A job fires once per date value; when the Issue's date changes the worker follows its events and waits for the new instant instead, and a date moved into the past is treated like any missed occurrence under the job's `catchup`. An `execute` job on an Issue date runs its prompt as any prompt job does. The worker also delivers adapter `notify` jobs on an existing Issue, on any trigger: it puts the inbox request with the job's message (the Issue's id and title when blank) in the recipient's inbox, resolving `current-owner-or-author` from the Issue when it sends, and records a succeeded or failed run with no agent started. A zero-lead `current-owner-or-author` notification on an Issue date stays with kata's own date sweeper.
- The worker runs agent prompt jobs on their schedule: a `cron` trigger (five fields or descriptors such as `@daily`, in the trigger's time zone, read by kata's own parser), an `interval` or `@every` one (counted from the job's creation) and a `once` instant fire without a request, while `manual` jobs still run only on `tern-kata run`. `overlap: forbid` holds a job's next occurrences until its earlier run has settled, `allow` starts them as slots free, and occurrences beyond the Project's capacity queue and start oldest first (`worker status` shows the next run and the queue). After downtime or a pause, `catchup` `all` runs every missed occurrence in order, `latest` only the newest, and `skip` only the newest within `grace_seconds`; at most 7 days and 100 occurrences are kept per job, and the oldest overflow is dropped and logged. A run over `timeout_seconds` is stopped and failed with "timed out". Editing, disabling or re-enabling a job in kata changes its schedule within about a second, without restarting the worker, and a changed definition drops the occurrences still waiting. A per-run Issue gets its `scheduled_offset_seconds` and `deadline_offset_seconds` as its Scheduled and Deadline dates, counted from the occurrence.
- `tern-kata worker` runs kata's agent prompt jobs on your machine with no Tern window open: from `worker.toml` (executor label, served Projects with capacity, checkouts, Agent profiles, secret sources, limits) it runs each job's prompt through headless `omp` in the job's checkout, creates the run's Issue (or comments on the job's existing one), and records the run in kata as running, then succeeded or failed with the agent's final message and token counts. The agent is told its Issue and to comment and close it with evidence; an Issue left open gets the final message as a comment and the `needs-review` label. A run over its timeout is stopped and failed. Native jobs and Projects not listed in `worker.toml` never run, a second worker on the machine is refused, and a Project whose lease another worker holds admits nothing. A run whose agent may have started when the worker stopped is held as unknown, never sent again. Anyone who can write jobs in a listed Project can run prompts and commands on your machine; see the README.
- A worker that is stopped or killed and started again on the same state folder never sends a run's prompt twice: each run's journal is saved before every step, and a run whose agent may have started and whose outcome the worker cannot prove becomes a Held run, recorded `unknown` in kata with the reason first in its summary and a comment on its Issue (`launch_unproven`, `interrupted`, `no_receipt`, `group_unproven`, `agent_login`, `agent_quota`, and the nothing-started reasons), with its job's overlap gate closed until you settle it. `tern-kata worker resume <run-uid>` continues it as a new headless omp attempt on the saved session with a prompt that warns the previous turn may have partly run, and the run goes back to running; `tern-kata worker abandon <run-uid>` records it `cancelled` ("abandoned by <actor>") and frees its slot. `worker status` lists each held run with its reason and the commands that settle it, and the worker's control socket answers a run's detail (steps, session, output tail) and resume and abandon requests for a later Pane.
- The tern-kata plugin gains a host half (`host.luau`) that keeps the worker running with no Tern window open: when `worker.toml` exists it starts `tern-kata worker` in Tern's session daemon and starts it again whenever it exits, waiting 1 second, then 2, 4 and so on up to a minute, and again whenever the daemon starts. It finds `tern-kata` and `omp` even when Tern was started with a short `PATH`. With no `worker.toml` it does nothing. `tern-kata worker status` says whether Tern supervises the worker or it was started by hand; an empty `worker.manual` beside `worker.toml` turns supervision off (README, "Supervision").
- `tern-kata run <job-uid>` asks the running worker to run an adapter prompt job now; `tern-kata worker status` says what the worker serves, runs and refuses (including a Project another machine's worker owns), and `tern-kata worker doctor` checks `worker.toml`, checkouts, agent commands, secrets, kata and each Project's lease and says how to fix what is missing.
- The Page bar gains Runs (`4`): the Pane's Project's kata runs newest first, each a card with a status badge (`running`, `succeeded`, `failed`, `cancelled`, `unknown`), the job's or workflow's name, the Issue, the executor, start, duration (so far while it runs) and the summary's first line, whoever the executor was. Enter shows the detail: the whole summary message, token counts and the references kata holds; `i` opens the run's Issue on the Issues Page; `r` on the Jobs Page opens the Runs Page on the selected job's runs and `f` narrows or widens the list to the selected run's job. Kata lists 100 runs a page and filters only by job, so `m` reads the next older page; the Workflows Page shows each workflow's latest run on its row and its latest runs in its inspector, from the Project's newest 100 runs.
- An Issue a Cron job made is marked: its list row and Board card title start with "◷ " (after "↻ " when it also recurs), and its detail has a Cron job property naming the job (its uid when the job is gone) and the run's scheduled time in the Pane calendar. Enter on the property, or a click, opens the Jobs Page with that job selected. A parent's detail has a Cron jobs property listing its jobs with their state, pause reason and schedule, each one openable the same way, and a closed parent says its jobs are paused.
- The Page bar gains Workflows (`5`): the Pane's Project's kata workflows with their step counts, archived ones hidden until `a` shows them. Enter opens an inspector with each step's kind, command or prompt, the steps it waits for (`after review`) and its retries, and the live Cron jobs that run it (each row names them too); `n` and `e` edit a workflow as JSON in the Workflow card or in `$EDITOR`, checked locally against kata's rules (unique step keys, `after` naming earlier steps, retries 0 to 100, command or prompt) before it is sent, with the problem named and the text kept. A save is a Guarded write: a workflow changed meanwhile is not overwritten, and the card shows your text beside the new version with Overwrite and Discard Draft. `x` archives and `r` restores; archiving a workflow a live Cron job uses shows kata's refusal.
- The top bar has a Page bar, "1 Issues  2 Board": `1` and `2` or a click switch Pages, `b` still toggles between Issues and the Board, and each Page keeps its selection while the other is shown. The Board Page is what Board mode was; it shows the Pane's Project, the Project Collection if one is current, else the workspace's Binding (from Inbox or another fixed Collection in a bound workspace it switches to that Project), and with neither it says so and opens the Menu's Projects list.
- `3` shows the Jobs Page: the Pane's Project's Cron jobs, native and adapter, as cards with a state badge (`active`, `disabled`, `archived`, `paused: parent closed`, `paused: parent deleted` or `paused: Project archived`), name, kind (`recurring child`, `agent prompt`, `workflow`, `notify`), schedule in words ("every weekday at 09:00 Europe/Berlin", "every 15 minutes", "once at 2026-11-01 09:00 UTC", "manual", "2 days before the Issue's deadline"), agent profile and next run in the Pane calendar's zone. A schedule that can't be read, or a next run that can't be worked out, is left off. Archived jobs are hidden until `a` shows them, `ctrl+r` and daemon events read the jobs again, and at 140 columns and wider an inspector shows the selected job's full definition and, for a recurring child, its parent Issue and delivery progress; Enter on that parent opens it on the Issues Page. The help sheet lists the Jobs keys.
- `b` in a Project Collection switches the list to a Board: a column for No lane (open Issues with none of the Lane labels, even one labelled only `bug`), one per Lane (`needs-triage`, `needs-info`, `ready-for-agent`, `ready-for-human`, each with its card count) and Done (Issues closed in the last 14 days, at most 20, newest closed first; the header reads "Done 20 of 192" when more qualify). Each Lane header is a badge in its own theme tone (No lane muted, `needs-triage` warning, `needs-info` error, `ready-for-agent` info, `ready-for-human` user, Done success; custom Lanes take the other tones in turn). A card shows its short id as a badge in its Lane's tone, then its priority as a badge (`P0` error, `P1` warning, `P2` info, other priorities muted; none without a priority, kept on Done cards), its title over at most two lines (muted on a Done card; a recurring Issue's starts with "↻ ", as in the list) and its labels that aren't Lane labels as info badges; an Issue with several Lane labels shows once, in the first Lane, with "also: …", and a Done card says which Lane `r` reopens it into. The selected card shows its full title, its owner as a user badge and every label. `↑`/`↓`/`j`/`k` move within a Lane, `←`/`→` across Lanes (skipping empty ones), a click selects a card, and the Issue keys, `x`, `r`, the filters and the live refresh work as in the list. `b` again returns to the list with the same Issue selected, and `b` with no Project to show says the Board needs one and opens the Menu's Projects list. The Lanes share the Pane's width, from 140 columns up, with card text wrapping to fit, and each Lane's cards scroll inside a list that fills the Lane down to the footer, sized from the Pane's rows, so the top bar stays in view. The footer lists `+`, `-`, `a` and `A` for the selected card on the Board and in the Lane view. An open card with a deadline or scheduled date shows one Date badge after its priority badge, for the most pressing date ("overdue 2d" error, "due today" warning, "scheduled 3d ago" warning, "scheduled today" accent, "due tomorrow" warning, "due 10-24" and "scheduled 10-28" muted; another year reads YYYY-MM-DD), and the selected card shows a Dates line ("scheduled 2026-10-28 · due 2026-11-02"); both read dates as the Today, Upcoming and Deadlines Collections do and move on at local midnight.
- `>` and `<` on the Board move the selected card one Lane right or left among No lane and the Lanes. The target label is added first, then the other Lane labels are removed, so a failure leaves the Issue in two Lanes, never none; an Issue with two Lane labels ends with one. The card shows in its new Lane at once, a failure leaves a Notice with the daemon's reason, and a Move is refused while the daemon is disconnected.
- An open Board card that an open Issue blocks shows a "blocked by 8gm4" line in the warning tone, on every card whether selected or not. It lists every open blocker (qualified `project#id` outside the Project, cut to three and "+N"), counts blockers the Board doesn't draw, and never shows on Done cards or once the blockers are closed.
- Selecting a Board card highlights the cards related to it: each gets a badge beside its short id (`parent`, `child`, `blocks this`, `blocked by this`, `related`, as seen from the selected card) and a ring in the Relationship's tone (accent, info, error, warning, neutral). Several Relationships show every tag, and the ring follows blocks this, blocked by this, parent, child, related. The selected card keeps its ring, Done cards stay muted, and the Lane view shows no highlight.
- The selected Board card shows a Relationships line: its parent, its child count ("6 children, 2 open"), the open Issues it blocks, its open blockers and its related Issues, with empty parts left out and ids qualified outside the Project and cut to three and "+N". Each id is clickable and selects that Issue's card, revealing it in its Lane; an Issue the Board doesn't draw opens in the detail beside the Lane view, and Esc goes back to the card. `^` on the Board or in the Lane view selects the parent's card the same way, and leaves "<id> has no parent." without one. The help sheet's Board group lists `^`.
- Enter or a double-click on a Board card opens its Lane view: that Lane's Issues as a full-width list under a Lane header, with the Issue detail beside it at 140 columns and wider. It has the list's keys; `←`/`→` switch Lanes, `<` and `>` Move the card and select the next card in the Lane, and Esc returns to the Board with the card kept.
- A Pane under 140 columns opens the Board Page in the Lane view, on the selected Issue's Lane, so `B` and the Move keys work there too.
- `B` on the Board or in the Lane view opens the Lanes card: a wide card with a Lane list section (the Project's Lane list as comma-separated names, its help under it) and a Done section ("Days back" and "Most cards", with the defaults 14 and 20 as placeholders; `tab` moves between fields; blank restores the default 14 and 20, anything but a positive whole number, at most 3650 days and 500 cards, is refused naming the field). `enter` saves it to the Lane list file and the Board's columns change, and the card stays open, locked, until the save answers: it closes on success, or shows the reason with your text kept; `esc` cancels. Names are tidied to labels (`In review` reads `in-review`), and an empty name, a name over 64 characters or a duplicate is refused with a message naming the entry. An empty field restores the default list. A muted "Not Lanes yet" line under the Lane list names the labels on loaded Issues that aren't Lanes. `B` waits, with a Notice, until the saved list has loaded, and opens nothing, with the file's error as the Notice, while the Lane list file is unreadable. Saving never changes a label in kata.
- The Board's Lanes come from the Project's table in `lanes.toml` under tern-kata's folder of the user config directory, with optional `done_days` and `done_cards` beside the labels, read each time the Board turns on or the Project changes; a done_days above 3650 or done_cards above 500 counts as unset; a missing file or Project gives the default Lanes, and an unreadable one gives the default plus a Notice and is never overwritten.
- `d` on the selected Issue (list, Board, Lane view, Issue detail) opens the Dates card: Scheduled and Deadline fields, prefilled, taking `YYYY-MM-DD`, `today`, `tomorrow`, `+Nd` and `+Nw` against the Pane calendar's date with a muted weekday preview; blank clears and anything else is refused naming the field. Saving writes the changed dates only to the Issue's `scheduled_on` and `deadline_on` metadata, each guarded on the value the card opened with, so a date changed elsewhere is reported and not overwritten; a date kata holds with a time is left alone unless edited.
- The Create card (`n`, `N`) has Scheduled and Deadline fields after Priority, taking the same `YYYY-MM-DD`, `today`, `tomorrow`, `+Nd` and `+Nw` input with a muted weekday preview as the Dates card; an invalid date is refused naming the field and nothing is created. The dates are sent in the one create request as the Issue's `scheduled_on` and `deadline_on` metadata, and none when the fields are blank.
- Every single-line text field has a movable caret: Create, Close, Recurrence, New Project, the single-field forms, the Lanes card, the Dates card, the Filter form, the Menu filter and Search. `←`/`→` move it a character, `Home`/`End` or `ctrl+a`/`ctrl+e` to the ends; typed and pasted text goes in at the caret, Backspace deletes before it, Delete after it, `ctrl+u` clears the field. The Menu keeps `Home`/`End` for its entries (`ctrl+a`/`ctrl+e` move the caret), and the Filter and Recurrence cards keep `←`/`→` for their choice fields.
- The Job card makes and edits the jobs a worker runs too: its Kind field gains Agent prompt, Workflow and Notify beside Recurring child (a job being edited keeps to its own side). Agent prompt has a multi-line Prompt (Enter adds a line); Workflow a picker of the Project's live workflows; both an Agent profile (`options.profile`, other options kept), a Checkout (`checkout_key`), Secrets (`ENV=source` pairs, `secret_refs`), the Run Issue policy (a new Issue per run with title, body and scheduled and deadline offsets such as `1d` or `-2h`, or an existing Issue by short id), Overlap and a Timeout. Notify names an existing Issue, a recipient and a message. The profile and checkout fields are pickers of this machine's `worker.toml` (read with the worker's own parser each time the card opens) and free text without one, or with one that can't be read, which the card says. Every trigger is offered to a worker's job: cron, interval (no 60-second floor), once (a full RFC 3339 instant), manual, Issue's scheduled date and, for Notify only, Issue's deadline with a lead; the preview reads once and Issue-date triggers in words. Catch up with grace applies to cron, interval and once triggers. A blank prompt, a workflow that isn't a live one of the Project, an Issue-date trigger or existing-Issue policy with no Issue, a once instant without its offset, a malformed secret or checkout key, a named recipient without a message and a span out of kata's range are refused naming the field and nothing is sent; a target Issue that doesn't exist is refused the same way by the write. The help sheet lists Enter (new line in the prompt) and the kata skill shows how to define the jobs.
- The Job card makes and edits recurring-child jobs: `n` on the Jobs Page opens it for a new job, `J` on an Issue (list, Board, Lane view, Issue detail) for a new job with that Issue as its parent, `e` on the selected job, prefilled. It has a name, a trigger (a cron expression with its time zone, or an interval of at least 60 seconds), the parent Issue's short id, a child title and body, an inbox recipient (blank is the parent's current owner or author) and message, a catch-up choice (latest, every missed run, or skip with a grace) and Enabled; fields that don't apply are hidden and skipped by `tab`. Under the trigger a live preview reads the schedule in words and lists the next three runs. `ctrl+o` saves; a bad cron expression, unknown time zone, interval under 60 seconds, skip without a grace or blank name or child title is refused naming the field and nothing is sent. An edit is a Guarded write: a job changed meanwhile is not overwritten, the card shows the newer job and keeps your draft, and `o`, `u` or `d` save the draft over it, replace the draft with it or discard the draft.
- `p` on the Jobs Page pauses a running job or resumes one that is not, `x` archives the selected job, or restores it when it is archived (listed with `a`); each is a Guarded write that leaves a job changed meanwhile alone and says so in a Notice.

### Fixed

- Beside each other, the Issue list and the Issue detail scroll inside their columns down to just above the footer at any Pane height, instead of stopping a little past half the window; they and the Board's Lanes also follow a Pane made taller or shorter without changing its width.
- The last card of every Board Lane stays fully visible while a Notice or the "disconnected" line shows under the columns.
- A Board card reveal queued for a card that a newer draw moved to another Lane or dropped from Done no longer ends the Pane with "Tern surface: unknown id".
- Backspace with the caret at the start of the Search field does nothing; it no longer resets the selection and runs the search again.
- Scrolling the Issue detail (`↑`, `↓`, Page Up, Page Down) while it shows an error line or an Issue that is no longer available does nothing instead of ending the Pane with "Tern surface: unknown id main.columns.detail.viewport.content".

## [0.3.0] - 2026-10-20

### Added

- `tern-kata recur <ref>` prints an Issue's schedule in words with the next Occurrence's date; with `--frequency daily|weekly|monthly|yearly` (and `--every`, `--on`, `--day`, `--month`, `--until` or `--count`, `--start`, `--zone`) or `--rule <rrule>` it makes the Issue recur or changes its schedule, and `--stop` stops it, from a shell or an agent without Tern. The flags go through the Recurrence card's own checks, so invalid input is refused with the card's messages and nothing is sent; a schedule changed meanwhile is printed, not overwritten. Refs, `--as`, the Binding rule and exit codes match `attach`. The kata and tern-kata skills now tell agents to use it.
- `tern-kata attach <ref> <file>...` and `tern-kata detach <ref> <name>` attach files to an Issue and remove them again from a shell or an agent, without Tern. `attach` prints each stored absolute path; both need the directory to be bound to the Issue's Project and exit 1 on any failure.
- An Attachment is a copy of the file in `.kata-attachments` at the root of the Project's primary checkout, which every linked worktree shares and which stays out of git; an empty `.gitignore` there is rewritten with `*` on the next attach. An `attachment.<name>` meta key on the Issue holds the copy's host and path. Detach clears the key, including one with an unreadable value, and deletes the copy only when it is on this machine and in that Issue's folder, saying what became of the file. A detach clears the key only while it still holds what was read: a pointer rewritten meanwhile survives with its file, and the refusal says the Attachment changed. When the key is cleared but the copy can't be deleted, `U` closes the form and `tern-kata detach` prints "Removed <name>; could not delete <path>: <reason>" on stdout, then exits 1 with the error on stderr.
- The Issue detail has an Attachments tab after Links. It lists the Issue's Attachments by name, each on its own row whatever the name; a file held on this machine is a link to the file (one on a Windows network share links as `file://server/share/...`), one held elsewhere reads "<name> on <host>", and an Issue with none says "No attachments, u to attach".
- `u` on the selected Issue, in the list or the Issue detail, asks for a file's path and attaches it. `U` lists the Issue's Attachments by name and removes the one chosen, and says so instead of opening a picker when there are none. Both keys explain why when the directory is not bound to the Issue's Project. Attaching is refused when this machine's host name can't be read, and a pointer with an empty host is never treated as on this machine. The footer and help sheet list them beside the label keys. A successful `u` shows "Attached <stored name> to <short id>", so a file stored as `shot-2.png` is named.
- Two agent skills ship with tern-kata: `kata` for working with the kata CLI and `tern-kata` for reading and attaching Attachments. `npx skills add Dangerboi/tern-kata -g` installs them (`bunx` works too), and the install scripts offer to run it when they run in a terminal, with `bunx` when Node.js is missing.

## [0.2.0] - 2026-10-19

### Added

- Install scripts (`install.sh`, `install.ps1`) download the latest release, verify its checksum and install the window plugin when `tern` is on `PATH`. The **Install tern-kata** palette command runs them in a new Pane.
- `tern-kata --help` lists the flags.
- `R` on a comment in the Comments tab opens the comment Draft as a reply. `ctrl+r` cycles the kind (reply, confirm, refute, supersede), and a confirm or refute under 40 characters is refused before it is sent. A duplicate reply shows kata's message and offers to send anyway.
- Replies in the Comments tab show their kind, whose comment they answer and, for a comment with replies, how many. `enter` on a reply jumps to the answered comment, even in another Issue.
- `O` on the selected Issue opens the Recurrence card. It makes an Issue recur with a form for frequency, interval, weekdays, monthly and yearly day, Start date, end (a date or a number of occurrences) and time zone, and it changes or stops the recurrence of an Issue that already recurs.
- The Recurrence and Filter cards respond to clicks on their choices, and the Recurrence card's Every field names its unit.
- The Issue detail reads a recurrence in words with the next date ("Weekly on Mon, Thu · next 2026-10-26"), or "stopped", and recurring Issues carry a marker in the list.
- An owner with a timed claim reads "owner until 14:30" wherever an owner shows (list, children table, Issue detail).
- `I` opens the Inbox. `ctrl+n` and `ctrl+p` move a row, and `ctrl+v` and `alt+v` page.
- The children table has an owner column, a header row and alternating shading.

### Changed

- The Issue list draws each id in its Lane's Board colour (Done's for a closed Issue) and each owner in the user colour, as the Board does; where a list span has no such colour it takes the nearest text colour. A Project's Lane list now loads when the Project opens, not only when the Board turns on.
- The Issue detail uses the Board's colours: the heading's `#id` takes the Issue's Lane tone (Done's for a closed Issue), the owner is a user badge, labels are info badges, and Scheduled and Deadline are badges toned by their own date under the Date badge rules (muted on a closed Issue or before the Pane calendar's date is known).
- tern-kata requires the kata v0.19.0 daemon. Against an older daemon the Pane refuses to connect and says to upgrade.
- Saving a Draft and posting a comment or reply conflict only when the Issue's text changed. An agent claiming the Issue, a claim expiring or an owner change no longer causes a conflict. Closing succeeds while the Issue is open, and if someone closed it first the Close card says so.
- The Pane finds the daemon the way the kata CLI does, so it works without `kata` on `PATH`. Connecting gives up after 10 seconds instead of hanging.
- A workspace bound to a Project the daemon does not know says to run `kata init`, for local and remote daemons alike. Only an unbound workspace opens the Inbox.
- The Logbook, Today, Overdue, Upcoming and Deadlines groups, detail times and the Recurrence card's Start date use your local time zone.
- Child counts arrive with the Collection, so a live refresh downloads nothing extra and a failed count no longer discards a Collection that loaded.
- The footer shows each place's hints in kata tui's order and words and wraps them into a grid instead of hiding the ones that do not fit. The Issue detail footer adds label, owner, parent and priority hints.
- Going back after a jump returns to the tab and row you left.
- Compact activity lists the oldest entry first.
- A kata link opened in Tern reuses a kata Pane only in the current tab.
- Every card button names its keys, for example "Keep editing (n / esc)", including the Filter card's Apply and Cancel.
- Comments, replies, new Issues and closes can be sent again safely after a lost answer, without duplicating. A Recurrence change that keeps losing a race to another edit says so in plain words.

### Fixed

- Today and the other date groups move to the new day at local midnight, also when the machine slept through it.
- Text written in `$EDITOR` is kept in a file, and its path is printed, when Tern cannot be reached after the editor closes.
- `--as` and `--issue` refuse a value that is another flag, so `--as --issue x` no longer starts tern-kata as the actor `--issue`.
- `install.ps1` parses, keeps `%VAR%` entries in `PATH` and says when it changes `PATH`, so programs started from Explorer, such as Tern, see it.
- **Open kata**, `F9` and kata links open tern-kata in a new tab, in the focused Pane's directory, when Tern can't split the focused Pane, instead of doing nothing.
