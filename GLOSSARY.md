# Glossary

**Pane**: The Tern area the program draws into. _Avoid_: block (in Tern a block is a pane type; in kata `blocks` is a link).

**Page**: One of the Pane's top-level views, chosen from the **Page bar**: Issues (the list and the Issue detail), Jobs, Runs, Workflows, Board and Attention. Each Page keeps its own state, such as its selection, loaded runs and filter, while another is shown. Each Page that acts on a Project records the Project its state was filled for, by uid, and one rule resets that state (job filter, archived toggle, selection, held data, Lanes) whenever the Pane's Project differs, on entry and after every step; request counters survive it, so a read asked before the reset is ignored. The Attention Page acts on no Project, so it records none and its state survives every Project and Collection change. Each Page declares what its second column is, and one leave rule reads that: the Jobs and Runs Pages' second column is their own inspector, so leaving returns focus from it to the Issue list and gives the Issue detail column back as it was before the Page (the Attention Page, one full-width list with no second column, is declared the same way); the Board and Workflows Pages' second column is the Issue detail, so leaving keeps focus on it when it has focus, and otherwise gives the column back as it was. Every leave also clears the Page's loading markers, scrolls the list to the selection and loads the selected Issue's detail again. _Avoid_: tab (Tern's tabs and the Issue detail's tabs).

**Page bar**: The row in the top bar that names the Pages, each key drawn as a keycap like a footer key hint (`1` Issues, `2` Jobs, `3` Runs, `4` Workflows, `5` Board, `6` Attention), and a **Lettered Page** while one is shown (`C` Credentials, `F` Federation, `D` Daemons, `K` Config); a click on a Page presses its key. _Avoid_: tab bar.

**Issue**: One unit of tracked work in kata, as kata defines it.

**Project**: kata's namespace for issues, links, labels and events.

**Binding**: The Project a workspace names in its `.kata.toml`, or failing that its git alias. A workspace with neither is unbound and opens the Inbox.

**Collection**: A named set of issues the user browses: Inbox, Today, Upcoming, Deadlines, All Open, Logbook, or one project. "Inbox" names this Collection (the Inbox Project's open Issues) and nothing else; the requests addressed to a person are **Attention requests**.

**Menu**: The popup inside the Pane that switches the current Collection, with a type-to-filter box that searches every level and lists the matches flat. Its top level holds the bound Project pinned first and marked current, **Views**, **Projects**, the Lettered Pages, Restore a deleted Issue (not offered to an account whose credential is limited to one Issue) and New Project; Views and Projects open a level of their own. The Views row names on the right the fixed Collection that is current, or the saved view while one is. It stands in for the Menu sidebar, which only an unbound directory shows, and only while a fixed Collection is current; the sidebar rests on the Views level. _Avoid_: palette (Tern's own command palette).

**Views level**: The Menu level `Views` opens: Back, then the fixed Collections (Inbox, Today, Upcoming, Deadlines, All Open, Logbook), the **Saved views** by name and **New view**. Back, esc or backspace return to the Menu's top level with the cursor on Views, as the **Projects** level (Back, then every kata Project, opened by `Projects` or `P`) does with the cursor on Projects. Every Collection one can open from an unbound directory's sidebar is a view, so its sidebar shows this level.

**Saved view**: A name for a base Collection (a fixed one, or one Project) with the Filter card's fields and a search text, kept in `views.toml` beside `filters.toml`, on this machine and for every Project. The Menu lists saved views by name after the fixed Collections on the Views level; opening one makes its base current with its filters applied together, and the filter line ends with "view <name>" while the filters equal it, as it ends with "default" for the Project's default. `c` clears the filters for this Pane only. A new view is made with **New view**, which opens the **View card** (Name, Base, the Filter card's fields and Search); `f2` edits the view under the Menu cursor and `ctrl+d` deletes it after "Delete view <name>? y/n". An owner of `@me` is the Pane's actor when the view opens. A view whose base Project is gone or archived stays listed with "(Project gone)" or "(archived)", and opening it says so and changes nothing. A name cannot equal a fixed Collection's title or key, ignoring case. The Pane reads the file when it starts and each time the Menu opens; `tern-kata views` works on the same file. _Avoid_: preset, saved search.

**Blocking link**: kata's `blocks` / `blocked_by` relationship between two issues. _Avoid_: block, blocker.

**Draft**: An unsaved edit to an issue's text or fields, kept until the user saves or discards it, even if the issue changes underneath.

**Popup card**: A card drawn over the columns that takes the keyboard until closed: Create, Close, Recurrence, the Draft editor, the single-field form, New Project, the Lanes card, the Dates card, the Move card, the Delete card, the View card, the Backfill card, the Worker card, the Menu and the Filter form. When several are open, one order (`TopCard`) decides which takes the keys, is drawn and holds the text caret; the help sheet covers them all. A card may hide fields that do not apply to its state (the Recurrence card does by frequency), and tab skips them. Each card states one busy condition (saving, asking to discard, showing a conflict, answering a restart question, refusing): while it holds, focus does not move and no text caret sits in the card, and the caret otherwise sits in the focused field when the card does not hide it and it takes text; the Draft editor and the Workflow card state the same condition for their one body. Every card with fields shares one set of field-editing actions (next field, previous field, next choice, previous choice, delete, clear); a card declares which it offers and keeps its own wording ("clear filter", "clear name"), and one step applies the field moves and choice keys before the card's own key handler, while delete and clear reach the one text editor. Each card declares which global chords it lets through (only `ctrl+c`, from the Menu, Close, Recurrence and New Project). A card's order, modes, key handler, fields, busy condition and field-editing rows are declared once, in its entry of the card table; its own key bindings are rows of the card keymap, and how it is drawn is declared beside the drawing. The card tests walk the table, so a card that is not drawn fails them. _Avoid_: layer, modal, overlay (Tern's element name).

**Issue detail**: The column showing one Issue: its properties, Children and Activity tabs, with its own row cursor and jump history.

**Pane driver**: The step that turns one Tern input or daemon result into the next state, the view to draw, the Tern ops to send and the daemon commands to run.

**Daemon gateway**: The module that runs one command against the kata daemon and returns exactly one result message. Every command it handles is declared in one table: the steps before and after, and for a daemon call its workspace, the call and the failure message its error becomes. It also runs the Pane's timed waits: the stream's reconnect delay and the end-of-day wake, which it checks against the wall clock at least once a minute.

**Daemon catalog**: The daemons kata's own `config.toml` names, read in file order with the active one and `[tui].confirm_quit`; a missing file is an empty catalog. A remote entry is reached with its url and the token it carries (an inline `token`, else what its `token_env` variable holds); kata's client lists the entries and connects a local one by name (a remote one is connected by tern-kata, with only its own token, because kata's client would let `KATA_AUTH_TOKEN` replace it), and a stopped local one is started first, through kata's client, by `kata --daemon <name> daemon recover` (a profile) or `kata daemon start` (the current home) when the Pane switches to it deliberately (the one case in which tern-kata starts a daemon). The **Daemons Page** lists it and switches the Pane's connection to an entry, for this Pane only. tern-kata still reads the file itself for what kata's client does not expose (an entry's url, token, `allow_insecure`, `home`, `instance_uid` and `[tui].confirm_quit`), to set a started agent's environment, reach a remote entry or hub with its own token, and tell which entry a connection is. _Avoid_: daemon list, profiles file.

**Undo history**: The last 20 completed changes this Pane made to Issues, newest last, across Issues, held in memory for the connection. `u` takes the newest back with its inverse (close and reopen, owner, priority, label, body, link, Lane Move, Dates card change, delete), after kata tui's guards. Every other Issue write clears it with its reason, and so does an unknown outcome. _Avoid_: undo stack, edit history.

**Guarded write**: A write the Daemon gateway applies only if the issue has not changed in a way that matters since the user saw it: saving a Draft of the issue's text, posting a comment or reply, closing, and changing or stopping a Recurrence. A Draft or comment conflicts only when the issue's text differs from the text the Draft started against; a revision that moved for another reason (owner, status, claim, expiry) is written against as it now stands. Closing succeeds while the issue is open and reports an issue closed meanwhile without writing; kata enforces this atomically for a close sent with its idempotency key. A Recurrence change is guarded on the Recurrence's rule, start date and time zone: it conflicts only when one of them differs from what the Recurrence card opened with, and then writes nothing and shows the current schedule; a revision that moved because an Occurrence was created is written against as it now stands. A stop is guarded on the same three: it deletes the Recurrence at the revision it has now while they match what the card showed, and when one differs it writes nothing and shows the current schedule; one already stopped is reported without writing.

**Pane calendar**: The day and time zone the Pane reads every date in. Today's date and zone arrive with each Collection snapshot, and the day ends at the first instant of the next local date (local midnight, or the first moment after it where daylight-saving time skips midnight), when the Pane reads the Collection snapshot again.

**Collection snapshot**: What the daemon says the shown Collection holds for the current Collection and filters. One path loads it for the first load, a Collection switch, a filter change, an id search and a live refresh; a result is applied only if it answers the current query.

**Creation line**: The line kata tui shows for who created an Issue or a comment, built from the attribution kata returns: "creation: verified|pending|legacy" (an unknown state reads legacy), "accountable: <actor>" only when verified and set, and "source: <source actor or author>" with " / <teammate>" when there is one, joined by " · ". The Issue detail shows it under its properties and each comment on its row; nothing is shown when kata returns no verification state.

**Reply**: A comment that answers another comment, with a kind: reply, confirm, refute or supersede.

**Comment link**: One end of a Reply as seen from a comment on the Issue detail's Comments tab: the comment it answers (if any), then the Replies to it on any Issue. `]` and `[` choose one, wrapping around, and `enter` jumps to it, across Projects.

**Recurrence**: kata's schedule that creates the next Occurrence of an Issue when the current one closes as done. Stopping it creates no further Occurrences and leaves the existing ones as they are.

**Occurrence**: An Issue a Recurrence created, or the Issue that was made the first one.

**Attachment**: A file on an Issue, stored by kata: its bytes are in Docbank and the Issue holds one `attachment.<id>` meta key with `{name, media_type, size, docbank_version}`. The Pane uploads with `@`, lists them on the Attachments tab and unlinks one with `U`; unlinking clears the key and leaves the bytes in Docbank. A click or `enter` downloads one to a cache folder and opens it only when its name ends in an image, video, audio, PDF or plain-text extension (any other file is saved and not opened): in Tern's preview block with `tern open --preview` for images, `.txt`, `.md` and `.json` when run in a Tern Pane, else with the OS, when the notice says "outside Tern". Needs a `[docbank]` section in the kata daemon's config. _Avoid_: image, pointer.

**Old attachment**: A file tern-kata kept itself before kata stored them: a copy in `.kata-attachments/<Issue ULID>/` at the root of the Project's primary checkout, pointed to by one meta key holding `{"host", "path"}`, the OS host name of the machine with the copy and its absolute native path. The key is `tern-kata.attachment.<name>` and, from 0.3, `attachment.<name>`. `tern-kata migrate-attachments` moves the old attachments whose host is this machine (compared without regard to case) to Attachments.

**Primary checkout**: The main worktree of a git repository, the parent of git's common directory; every linked worktree shares it.

**Board Page**: The **Page** that shows one Project's Issues as a Board instead of the list (Board mode before Pages existed). It is Pane state that is not saved, the Pane starts on the Issues Page, and it ends when the Collection is not a Project. It acts on the Pane's Project: the current Project Collection, else the Binding. A Pane narrower than the side-by-side width shows the Lane view in place of the Board. In code and on the help sheet "focus" already means the focused column, so no Board Page term uses it.

**Board**: All Lanes side by side, in place of the list column, with the Issue detail column hidden: No lane, one Lane per Lane label, then Done. Each Issue is a card; the selected card shows its full title, owner and labels.

**Relationship**: A parent, child, Blocking link or related link between two Issues, as seen from one of them; the word the Filter form already uses. Read from the Collection snapshot's links, so it counts Issues the Board doesn't draw. _Avoid_: relation, dependency.

**Blocked marker**: The "blocked by 8gm4" line, in the warning tone, on an open Board card that at least one open Issue blocks. It names the open blockers, qualified (`project#id`) outside the Project, cut to three and "+N". Done cards never show it.

**Date badge**: The one date badge of an open Issue: on a Board card, in the id row after the priority badge, and on an Issue list row, after the title (dropped there when the whole title and the badge do not fit), for the most pressing of its deadline and scheduled date, worded in the Pane calendar's terms: "overdue 2d" (error), "due today" (warning), "scheduled 3d ago" (warning), "scheduled today" (accent), "due tomorrow" (warning), "due 10-24" (muted), "scheduled tomorrow" and "scheduled 10-28" (muted); another year reads YYYY-MM-DD. Done cards and undated cards have none.

**Dates line**: The line on the selected Board card giving both dates in full, "scheduled 2026-10-28 · due 2026-11-02", absent parts left out and no line without dates.

**Relationship highlight**: What the Board draws on the cards related to the selected card: a badge beside the short id in the card head naming the Relationship as seen from the selected card ("parent", "child", "blocks this", "blocked by this", "related") and a ring in the Relationship's tone. A card with several Relationships shows every tag; its ring takes the first of blocks this, blocked by this, parent, child, related. Only the Board draws it, not the Lane view.

**Relationships line**: The line on the selected Board card that names its Relationships: "parent zpxs, 6 children, 2 open, blocks e000, blocked by 8gm4, related 7x74", empty parts left out. Each id is a click that selects that Issue's card, or opens its detail when the Board doesn't draw it; `^` does the same for the parent.

**Lane view**: One Lane as a flat, full-width list under a Lane header line, with the Issue detail column beside it (only the focused column in a Pane narrower than the side-by-side width). Enter or a double-click on a card opens it, `←`/`→` switch Lanes, and Esc returns to the Board. The name avoids "focus", which already means the focused column.

**Lane**: One label of the Lane list, shown as a column and titled from its label ("ready-for-agent" reads "Ready for agent"). Every Lane stands for one kata label, so the Board is a view of kata data, not a copy.

**Move**: Taking an open card one Lane left or right (`<`, `>`) among No lane and the Lanes, never into or out of Done. One daemon command adds the target Lane's label (if missing), then removes the Issue's other Lane labels.

**Lane label**: Any label of the Lane list. An Issue whose only labels are not Lane labels has no Lane label.

**Work attention**: kata's coordination signal on an Issue, the `work.attention` metadata key (`needs-human`, `stuck`, or `ok`) with its `work.attention_msg`. It is not a **Lane label**, which is tern-kata's board state, and not `needs-review`, which marks a result nobody has checked yet (the worker's label on an open Issue after a run, with a comment). An agent started on an Issue writes it when it stops without closing; kata-plugin or any other agent may write it too, and the Pane shows it the same: `needs-human` (warning) or `stuck` (error), as its word alone beside the **Agent badge** on the list and Lane rows (so the title keeps its room) and as a badge on the Board card, and as the word with the whole message in the Work attention property of the Issue detail, on open Issues only (a closed Issue's leftover value shows nothing). `ok`, an absent key and an unknown value show nothing. It is a signal on the Issue that anyone reading it sees; an **Attention request** is a `notify.<address>` slot addressed to one **Inbox address**, listed on the **Attention Page**. _Avoid_: attention (alone: that is the **Inbox**'s notification slot), flag.

**Dates card**: The Popup card `d` opens on the selected Issue in the list, the Board, the Lane view and the Issue detail. Two text fields, Scheduled and Deadline, prefilled with the Issue's dates; each takes `YYYY-MM-DD`, a local `YYYY-MM-DDTHH:MM[:SS]`, a UTC `YYYY-MM-DDTHH:MM:SSZ`, `today`, `tomorrow`, `+Nd` or `+Nw` against the Pane calendar's date, previews the date it resolves to with its weekday (and time), and clears the date when blank. Saving sends one command for the changed fields only; the Daemon gateway patches the `scheduled_on` and `deadline_on` metadata keys one at a time, each guarded on the value the card opened with, and stops at the first failure. A key changed meanwhile is reported, not overwritten, and its field is refilled with the current value. It lets no global chord through. _Avoid_: date form, schedule card.

**Move card**: The Popup card `M` opens on the selected Issue in the list, the Board, the Lane view and the Issue detail, to move it to another Project through kata's move action (not the Lane **Move**). It lists the Collection snapshot's Projects without the Issue's own and the archived ones, filtered by the typed name; `enter` on one sends the move as a dry run and shows what kata would do (the Project it moves to, not the new short id, which kata assigns only on moving) or kata's refusal, and `enter` again moves. kata moves the Issue with its descendants, which the preview names, unless the card's "Only this Issue" switch (`o`) is on. The move is a **Guarded write** on the revision the card opened with, the preview included; a conflict keeps the card open and offers a fresh preview. After the move a Notice names the new `project#id` as a link that opens the Issue, and the move clears the undo history. It lets only ctrl+c through. _Avoid_: project picker.

**Delete card**: The Popup card `X` opens on the selected Issue in the list, the Board, the Lane view and the Issue detail, to soft-delete it through kata's delete action. It names the Issue's qualified id (`project#id`) and title, says a deleted Issue can be restored, and has two fields: the qualified id, or `DELETE <qualified id>` as kata tui asks (surrounding spaces ignored), which must be typed before `enter` sends the delete, and an optional reason, which the Pane writes as a `Deleted: <reason>` comment on the Issue before the delete (kata's delete records none). The delete carries kata's confirmation, `DELETE <qualified id>`, as the CLI's `kata delete` does; kata's refusals show on the card. A delete enters the **Undo history**, so `u` restores the Issue. Purge, which cannot be undone, is not offered. The Menu's **Restore a deleted Issue** brings back an Issue deleted earlier: a single field taking a short id, `project#id` or a ULID, which reads the Issue with deleted Issues included, shows its title and that it is deleted, and restores it on `enter`; that restore clears the undo history. Neither `X` nor the Menu entry is offered to an account whose credential is limited to one Issue. _Avoid_: trash, purge.

**Default filter**: A Project's saved field filters (project, status, owner, label, relationship; never search text), set with `ctrl+d` in the Filter form and kept in `filters.toml` beside the Lane list file. A Pane starts with its bound Project's default applied; `c` clears it for that Pane only. _Avoid_: saved search, preset.

**Results**: The flat list a text search or a search by meaning shows in place of the Collection's grouping. Field filters keep the Collection's grouping and headings.

**Search by meaning**: The other mode of the search box, switched with `ctrl+t` from by words (the text filter). Inside one Project, `enter` runs kata's own search of that Project (words and meaning together when kata's embeddings work, words alone otherwise) with the Status and Label filters (no Status on the Board) and lists the best 50 Issues in kata's order as **Results**; typing runs nothing. Where kata could only search by words, the search line says "kata searched by words" with kata's reason. The Owner and Relationship filters don't apply to it, and changing the Project, Status or Label filter afterwards, or switching Collection, ends those Results, leaving the words filter on the same text; Results asked without a Status that kata did not cut at 50 stay under a later Status, trimmed to it. `esc` out of the query puts back the search the box opened on (unless the Collection changed meanwhile), and a new search starts by words. A saved view and the **Default filter** keep only the text. The Pane can turn embeddings on for the connected daemon with the Search by meaning card, opened from the Config Page's row or, when kata searched by words with no reason and would take a turn-on, from the search line's Turn on… button or `ctrl+o`; kata's own `kata daemon local-embeddings` and Settings do the same. _Avoid_: semantic search, AI search.

**Search by meaning card**: The Popup card that `enter` on the Config Page's Search by meaning row, `ctrl+o` or the search line's Turn on… open, on its question while kata would take a turn-on from this account (after a failed setup it first shows kata's error, and `s` asks again); `s` on the row always opens it on the question. It asks before anything starts (kata uses your Ollama or its built-in model already on the kata daemon's machine, or downloads about N MB to it), and `y` sends the one request that starts kata's setup job while `n` and `esc` send nothing. It then follows the job with the row's words and a progress bar for the download and the indexing; the job runs in the daemon, so closing the card leaves it going. When the job is done it asks before running `kata daemon restart` for a local daemon (`n` closes the card and the row's `r` asks again) and names the command for a remote one. _Avoid_: setup wizard.

**Lanes card**: The Popup card `B` opens on the Board or in the Lane view. Text fields hold the Lane list as comma-separated names and Done's limits, and a **Save to** choice says where enter writes them: this machine (the Lane list file) or the Project (its **Shared Lane list**); it starts on the source in use, which the card names. An empty list field restores the default. `ctrl+x` stops sharing. Esc cancels. It lets no global chord through. Saving never changes a label in kata. _Avoid_: Lane editor, Lanes form.

**Lane list**: A Project's ordered Lane labels, with Done's limits. Read, in order, from the Project's **Shared Lane list**, else the **Lane list file**, `lanes.toml` in tern-kata's user config folder, else the default: `needs-triage`, `needs-info`, `ready-for-agent`, `ready-for-human`. Loaded when the Board Page turns on or the Project changes, and again when any Project's metadata changes. The Board names the source in use.

**Shared Lane list**: A Project's Lane list kept in kata, in the Project's `tern.lanes` metadata key (`{"labels": [...], "done_days": N, "done_cards": N}`), so every tern-kata on that daemon shows it. Written by the Lanes card as one write guarded on the Project revision the card opened with; a value that is not a Lane list is reported once and the Lane list file used. _Avoid_: project lanes, remote lanes.

**No lane**: The column of open Issues with no Lane label. It is always shown. An Issue with several Lane labels shows once, in the first of its Lanes in Lane order, with an "also" note naming the others.

**Done**: The column of Issues closed today or in the N days before it on the Pane calendar (default 14), at most M of them (default 20), newest closed first; N and M are per Project, set on the Lanes card or in `lanes.toml`. Its header says "20 of 192" when more qualify. It shows only what the Collection snapshot holds; the status filter does not apply to the Board. Each card names the Lane `r` would reopen it into, the Lane its labels point at.

**Worker**: tern-kata's kata adapter, `tern-kata worker`: a foreground process, one per machine, that runs the adapter prompt jobs of the Projects listed in its `worker.toml` through omp and records every run in kata. It reads its Projects' events, holds each Project's lease, and holds a run it cannot prove finished instead of sending its prompt again. It never runs native jobs and has no window or Pane. A Project listed in `worker.toml` is trusted: anyone who can write its jobs can run prompts on the machine as you, and commands too in a Project with `commands = true`. _Avoid_: daemon (kata's, Tern's), scheduler, runner.

**Group proof**: The answer to whether a **Run**'s process group (on Windows its Job Object) is gone: gone, present, or cannot be checked, with the reason. The platform adapters answer it; the Unix adapter never says "cannot be checked", the Windows adapter does whenever opening or querying the job fails for a reason other than "no such job". Callers settle a Run only on gone, so cannot be checked counts as not gone. The one termination policy (SIGTERM, SIGKILL ten seconds later on the worker's clock, a bounded wait) ends with a Group proof.

**Run lifecycle**: The module (`internal/worker/runlife.go`) that answers every question the worker asks about a **Run** from its journal and, where liveness matters, a **Group proof**: is it settled, is it held (before admission, or an uncertainty hold), does it owe a report or its settlement (a **Held run** never does), does it occupy a **Slot**, does it close its job's **Overlap gate**, may it be resumed, abandoned or cancelled (yes, or the refusal text), what recovery makes of a journal found at start, and the state name `worker status` shows. Callers ask it; nothing else compares a journal's phase or hold. The group proof is passed in, so a test can give any of its three answers.

**Slot**: One unit of a Project's run capacity. A **Run** occupies one from before its preparation while it is in flight, and a **Held run** keeps it only while its process may be alive: its **Group proof** is not gone, or it has no start record to prove anything by. A hold from before admission, and the secret, prompt and command holds once reported, free it at once. The **Run lifecycle** decides who occupies one.

**Overlap gate**: A job's `forbid` rule that admits no run while an earlier run of the job closes the gate: one that is not settled, or that settled as a hold needing the user. A settled run and a hold from before admission close none. It is separate from the **Slot**: a held run can free its slot and keep the gate. The **Run lifecycle** decides who closes it.

**Condition**: A rule in a job's `options.conditions` that a due scheduled occurrence of an adapter `execute` job must meet, or the worker skips it (ADR-0016). Read once into `cronjob.Conditions` beside `Adapter()`; an options value that does not parse is a condition that cannot be checked, which blocks the run (the occurrence stays pending, the job is shown blocked, the reason is logged once) instead of letting it start unchecked. Checked in admission, after the refresh of the definition and before a **Slot** is reserved, and only for an occurrence that has no run journal yet. The first conditions limit runs by count: `runs_per_day` and `runs_per_week`, counted from the run journals in the zone of the job's trigger, manual runs included, and by spend: `spend_per_day` and `spend_per_week`, the sum of the cost omp reported (`usage.cost.total`) in the run outcomes of the same windows, a run with no reported cost counting as $0 and making the total partial; Run now and `tern-kata run` are never checked. Stored with kata, so a worker that does not know them ignores them: the worker that holds the Project's lease decides. _Avoid_: filter, guard, rule (alone).

**Skip**: What the worker does with a due occurrence that fails a **Condition**: no kata **Run**, no per-run Issue, no **Slot**, no run journal. The occurrence leaves the job's pending list, so catch-up never retries it, and the **Overlap gate** is untouched. The worker keeps a skip record (job, occurrence, condition, reason, time) in its own state, in a per-Project file beside the run journals and pruned by the same retention; `worker status` lists each job's recent skips with a count and the latest reason. Not a Run status: kata has none called `skipped`. _Avoid_: cancelled run, missed run (that is what catch-up decides about occurrences it never admits).

**New commits**: The **Condition** `options.conditions.new_commits` (`true`, or an object with `folders`): a scheduled run starts only when the branch of the job's checkout (`checkout_key`) has commits, optionally touching one of the folders, since the commit the job's last succeeded run started at (its **saved commit**, kept per job in the worker's state). The first occurrence records the branch tip and is skipped. A run notes its start commit in its journal when it is prepared and the saved commit moves to it when the run succeeds, Run now included; a failed, cancelled or held run and a skip leave it. The agent's prompt lists the new commits (ADR-0016). git failing, a missing checkout or a saved commit that is no longer in the branch blocks the run.

**Held run**: A **Run** the worker will not settle on its own because its outcome is uncertain: the agent may have started and the worker cannot prove how it ended (`launch_unproven`, `interrupted`, `no_receipt`, `group_unproven`), a provider failure needs the user (`agent_login`, `agent_quota`), or nothing was started for a reason the user must look at (`secret_unavailable`, `invalid_prompt`, `execution_error`). Kata records it `unknown` with a summary whose first line is `reason: <code>` and whose next line is the detail, kata's convention for a machine-readable cause; the worker never starts its prompt again and nothing restarts it automatically. The user resumes it (`tern-kata worker resume`, a new headless omp attempt on the saved session; the run goes back to running) or abandons it (`tern-kata worker abandon`, recorded `cancelled`). A run held before kata saw it (`admission_rejected`, `create_rejected`) writes nothing to kata and can only be abandoned. _Avoid_: stuck run, failed run (a failure the worker can prove is `failed`), paused.

**Agent profile**: A named omp command line in `worker.toml` (`[profiles.<name>]`: command, model, thinking level, extra arguments) that a job selects with `options.profile`, `default` when it names none. _Avoid_: agent (the program), config.

**Cron job**: kata's recurring or scheduled definition in one Project: a name, a trigger (cron expression, interval, once, manual, or an Issue's scheduled date or deadline with a lead), an action (notify, or run an agent prompt or a workflow), an Issue policy and the overlap and catchup rules. Kata stores it and reads it back; it also delivers a **native job**, while an **adapter job** is run by a worker on someone's machine. Archiving (kata calls it deleting) a Cron job stops it until restored. The Jobs Page lists them. _Avoid_: cron (alone), schedule (that is the trigger's words), task.

**Cron job module**: The leaf package `internal/cronjob` where the rules of a **Cron job** live, so the Pane and the worker read a job the same way (ADR-0011): the typed kinds of a trigger, an action and an Issue policy (a kind kata adds later stays representable), the Cron job value, which jobs are **native** and which **adapter**, the schedule of a job with its anchor rule (an adapter job's interval and `@every` count from its creation, a native job's interval from the delivery anchor on its parent, a native job's `@every` unanchored), Issues a day and the high-rate warning, and the prefix and reader of a native job's delivery state. It imports neither the model nor the worker nor kata's client; `internal/cronjobclient` beside it is the one translation from kata's client types. What only the Pane reads (a native job's parent, **pause reasons**, the words of a trigger, the Jobs Page's row) stays in the model. _Avoid_: trigger module, job parser.

**Workflow definition rules**: Kata's rules for a **Workflow**'s definition, held once in the **Cron job module** as `cronjob.ValidateWorkflow` over one decoded shape, `cronjob.WorkflowDefinition`: version 1, at least one step, then each step in turn (portable key, unique key, retries 0 to 100, `after` naming an earlier step, kind and its shape, options with no credential or local path), then the Workflow's options. It returns the first problem with one canonical message, the **Workflow card**'s wording, which the worker also uses when it refuses a Workflow (`internal/cronjobclient` translates kata's client Workflow into the shape). The Workflow card keeps what belongs to its text (JSON syntax, the name length and the 256 KiB size); the worker keeps its own ADR-0008 refusals and prompt budget, which are policy and not kata's rules.

**Native job**: A Cron job that notifies with a fresh Issue per run (`notify` action, `per-run` Issue policy), whatever its enabled state. Kata's own daemon delivers it: each due occurrence becomes a child Issue of the job's **parent** Issue, and the parent's `cron.progress.<job uid>` metadata records how far delivery has got (`anchor`, the job's creation, and `through`). The Pane reads that metadata and the parent's status. The Jobs Page calls it a "recurring child". _Avoid_: recurring job (a **recurrence** is the Issue's own RRULE).

**Cron-made Issue**: An Issue a native job created, recognised by its `cron.occurrence` metadata (`job_uid`, `definition_event_uid`, `scheduled_at`), which only kata's daemon writes. The list row and Board card carry a "◷" marker, distinct from the Recurrence's "↻", and the Issue detail's Cron job property names the job (its uid when the job is gone) and the run's scheduled time; Enter on it opens the Jobs Page on that job. The job's parent Issue shows a Cron jobs property listing its jobs. _Avoid_: occurrence (that is a Recurrence's Issue), generated Issue.

**Adapter job**: Any Cron job that is not native: it runs an agent prompt or a workflow, or notifies about an existing Issue or an Issue date. Kata never runs it; a worker does, so its interval counts from a start only the worker knows and the Jobs Page leaves its next run out. _Avoid_: external job.

**Pause reason**: Why a Cron job is not running, shown in its state: "archived", "paused: Project archived", "disabled", "paused: parent deleted" or "paused: parent closed"; a job with none is "active". Kata stores no pause, so the Pane derives it, in that order: the job's `deleted_at` beats everything, then an archived Project (read from the Project's own state, because kata answers none of its jobs), then `enabled: false`, then the parent's deleted or closed status. An adapter job may also read "paused: failed runs": this machine's worker stopped admitting its runs after `pause_after_failures` runs in a row recorded `failed` (default 3), keeps that in its own state, not kata's, and shows it in `worker status`; the Jobs Page reads it from the worker's status, and `u` or `tern-kata worker resume <job>` lifts it. Reopening the parent, restoring the Project or the job, or enabling the job resumes a native job, which owes a **Backfill** when its catch-up is `all`.

**Job card**: The Popup card that makes and edits a Cron job: `n` on the Jobs Page for a new one, `J` on an Issue for a new native job with that Issue as its parent, `e` on the selected job. A kind and a trigger each decide which fields it shows, and under the trigger it previews the schedule in words and the next three runs. A new job is sent at a uid the card made when it opened, so a resend is not a second job; an edit is a Guarded write on the job's `definition_event_uid`, and when that moved the card shows the newer job, keeps the Draft and takes an explicit choice to save over it, take it or discard. For an adapter job being edited it also shows the job's conditions, read-only, or the reader's error when they do not parse. It lets only ctrl+c through. _Avoid_: job form.
**Backfill**: The child Issues kata's daemon creates at once when a native job with catch-up `all` runs again after a pause: one for every occurrence after the parent's `cron.progress.<job uid>` `through` up to now. The Pane counts them from the trigger, its zone and `through` (kata advances `through` to the sweep time while the job runs, and stops advancing it while the job is paused), so an active job owes none. Reopening the parent, resuming the job and restoring the job each end a pause, so each first opens the **Backfill card** when the count is above zero. Nothing is asked for a job that catches up with `latest` or `skip`, one with nothing missed, or one that stays paused for another reason. _Avoid_: catch-up (that is the job's policy field), replay.

**Supervision**: The plugin's host half starting a worker, and starting it again whenever it exits, exactly when `worker.toml` exists and `worker.manual` does not. One Go module in the worker package owns the rule (the worker's restart promise on stop and the Daemon gateway use it); the Luau host half holds no copy: it runs `tern-kata worker supervised` (exit 0 and worker.toml's text when the rule holds and no worker runs, exit 4 and one line naming the worker when one already runs, exit 1 when the rule does not hold) and acts on the answer, so the halves cannot drift in the rule; the Go tests pin the answer. A worker the host half did not start is left running: a plugin reload or a Tern update's handoff loads the host half again while the worker its earlier load started runs on. On Tern 0.9.16+ Tern tells the new load when that worker ends, so the host half starts one at once and logs how the old worker ended; otherwise, and for a worker started by hand or after a daemon restart, it starts one within a poll (10 s) of its end. The halves are installed separately (the binary by `install.sh`, the host half with the plugin), so a binary older than the plugin may not know `worker supervised`: the host half then logs the status once per daemon and starts no worker until the binary is updated. The Worker card's switch turns it off by creating `worker.manual` and on by removing it. A worker the user started by hand is not supervised. _Avoid_: auto-start, keep-alive.

**worker.manual**: The empty file beside `worker.toml` that turns **Supervision** off. Creating it stops the plugin starting or restarting the worker, even with a `worker.toml`; removing it (or never creating it) leaves supervision on. The Worker card reads it and its switch creates or removes it. _Avoid_: lock file, disable flag.

**Worker card**: The Popup card `W` opens on the Jobs Page, from the list or the inspector, for the Project the Pane's folder is bound to. It shows, from one read of this machine plus the worker's own status, whether `worker.toml` exists, loads (or why not) and lists the Project with its checkout, whether a worker runs (process id, executor, runs in flight) and whether the plugin supervises it or `worker.manual` turned that off (see **Supervision**, **worker.manual**). With no file it offers Set up (executor and actor prefilled as `worker init` would; the Command field starts blank and shows the default as a hint, a blank Command meaning the default; model and thinking); with a file that does not list the Project, Serve this Project. Both show the checkout and the trust note and save only once the trust choice is yes, through the worker package's checked write; a refusal names the field and keeps the input. After a save with a worker running it asks how to restart it: when idle (the default, `i`) or now (`n`, naming the runs in flight), which sends the worker its stop request; with none running it says the plugin starts one. A folder bound to no Project gets a message and no fields. It lets no global chord through. _Avoid_: worker form, worker settings.

**Backfill card**: The Popup card that asks before a Backfill: the count of child Issues, job by job, and three choices: create them (`c`), switch the job to `latest` and go on (`l`), or cancel (`esc`, changes nothing). Switching is a Guarded write that replaces the job's catch-up before the resume, restore or reopen. It lets no global chord through.

**Run**: Kata's record of one execution of a Cron job or **Workflow**, written by the executor that ran it (an adapter, a worker, another machine's): its status (`running`, `succeeded`, `failed`, `cancelled` or `unknown`, the last for one nobody could settle), the job or workflow it names, the Issue it ran for, the executor's label, start and end, and a summary (message and token counts). Kata keeps it as a revisioned observation and lists runs newest first by when each was first observed. The Runs Page lists them. _Avoid_: execution, job run, history entry.

**Runs Page**: The **Page** (`3`) that lists the Pane's Project's **Runs**, with a detail (Enter) and a filter to one Cron job. Its default view lists every run read. `n` switches it to the since-you-last-looked mode: the runs that ended since the last mark, newest first, above a Now line, then the Project's next runs (native jobs with their next time, adapter jobs listed with no time since only the worker starts them); `s` marks them seen, at the newest end among the runs read. More than eight new runs fold into one row per job, failed runs never. The mark and the mode are per machine, in `seen.toml` beside `filters.toml` (one table per Project UID). Both views also list, at the top, one skip row per job whose due occurrences this machine's worker skipped (count, latest condition and reason, time of the latest), built from the worker's status rather than from kata, narrowed by the job filter and absent without a readable worker status; it is not a **Run** and cannot be selected. Its other state is Pane state that is not saved. It acts on the Pane's Project like the Board Page.

**Lettered Page**: A **Page** opened by a letter (`C` for Credentials, `F` for Federation, `D` for Daemons, `K` for Config) instead of a number, from any Page and from the Menu, where it is listed. The **Page bar** draws it only while it is shown, esc or backspace returns to the Page shown before, and it does not act on the Pane's Project and has no reset rule. Its state is Pane state that is not saved and is read again on every entry. _Avoid_: admin view, modal.

**Credentials Page**: The **Lettered Page** (`C`) that lists the daemon's API tokens as kata redacts them: state, id, name, actor, scope (global, or Project and root Issue uid), created, expires, last observed use and revoked, in UTC. It first reads the connection's auth capabilities: an account without token audit read sees "credential audit unavailable for this connection", never an empty list. The list refreshes every 30 seconds while shown, and `r` refreshes it or retries a failed check; the summary reads "N credentials · observed at <time>". `n` opens the **Token card** and `x` on a token asks before revoking it.

**Token card**: The **Popup card** `n` opens on the **Credentials Page** to create an API token, as `kata tokens create` does: actor (prefilled with the Pane's), name, expires in, scope (account, or an Issue subtree with the Issue, resolved to its Project uid and root Issue uid), teams and the token file. The secret goes from kata's answer into that new owner-only file and nowhere else: the Pane never draws, logs or holds it. _Avoid_: key card, secret card.

**Federation Page**: The **Lettered Page** (`F`) that lists this daemon's spoke federations, the Projects that replicate a Project on a hub, from the daemon's instance and federation status, in kata tui's words. A header names the active daemon, its endpoint, its instance uid and its auth; each row gives the Project, hub, actor, push, pending push count, last sync and badges (insecure, quarantine, reset, violations), and the selected row's hub URL and Project id, actor and credential sit under the list. Enter shows one Project's detail (capabilities, push, credential, `allow_insecure`, cursors, claims, quarantines, violations, last pull, push and sync, last error), esc or backspace returns to the list and then to the Page shown before, and `r` reads again. It says "loading federation status...", "no spoke federation enrollments" and "failed to load federation: <error>"; a failed read replaces the list until the next one. `x` leaves a federation: a preview (`d` detach or archive, `l` local-only), then the spoke's preflight, the hub's revoke of this spoke's enrollments (unless local-only) and the leave, then a result. `b` browses the Projects of the hubs in kata's daemon catalog, read only, and `n` enrolls a Project: choose a local Project (a new replica or one to adopt), a hub (never the active daemon or a local entry) and a hub Project, then a preview that names what blocks it and, for an adoption, a typed confirmation of the local Project's name; running it ensures the hub Project (same-name adoption only), enables federation and creates the enrollment on the hub, reads the hub Project's federation metadata with the enrollment's token and creates the replica on the spoke, then shows a result. A failure after the hub granted the enrollment keeps a recovery, where `R` reveals the `kata federation join …` command with its token. Its state is Pane state that is not saved.

**Daemons Page**: The **Lettered Page** (`D`) that lists the **Daemon catalog** with kata tui's columns (daemon, endpoint or "local", "token" or "no token", "current"), the selected entry's name and endpoint (and `allow_insecure`) under the list, and switches the Pane to the entry on Enter. A switch connects first and changes the Pane only when that works: the Daemon gateway then drops its client for the workspace, and the Pane resets its Collection, Pages, caches, undo history and event stream and reads the Project again. A failed switch shows `daemon "<name>": <reason>` and keeps the current connection; nothing is written to disk. With no entry it says there are no named daemons and where to add one. _Avoid_: server list.

**Config Page**: The **Lettered Page** (`K`) that lists tern-kata's config files on this machine, in this order: `lanes.toml`, `filters.toml`, `views.toml`, `seen.toml`, `worker.toml` (with its supervision), `agent.toml`, the Docbank row (the `[docbank]` section of the default kata daemon's `config.toml`: not set up, the Docbank on this machine, a Docbank at a url, or tern-kata's old pinned setup, on which `s` switches to kata's local Docbank after a y/n; no other form has a key), the **Search by meaning** row (after the Docbank row; `s` turns it on where kata allows this account to, and `r` restarts the kata daemon when a restart is owed, each behind its own question: kata's search by meaning status for the daemon the Pane is connected to, so it follows a **Daemons Page** switch; off, downloading, set up and waiting for a kata daemon restart, a failed setup, indexing with its progress, or on with the built-in model, your Ollama or another provider; read again every 2 seconds while a download or the indexing runs) and kata's own `config.toml` (read-only, the **Daemon catalog**'s file). Each row shows the file's absolute path, whether it is missing, loads or does not load (the error of the reader its feature uses, drawn in full under the list for the selected row) and a one-line summary, except that the Search by meaning row has neither a path nor a status (it is the daemon's answer, not a file); a missing file reads as what its absence implies (not created, no worker set up, the default agent settings, an empty catalog). One read per entry returns every row, and one file that does not load leaves the other rows showing. With no config folder it says so and lists no rows. `enter` on a row opens the card or Page that already edits the file (none for `agent.toml`, which `e` opens in `$VISUAL` or `$EDITOR` instead, checked before it is written). _Avoid_: settings page, preferences.

**Workflow**: One of a Project's kata workflows: reusable command and prompt steps, each with a key, optional `after` steps it waits for (earlier steps only) and optional retries (0 to 100). Kata stores it; a Cron job that runs one names it. Archiving one that a live Cron job uses is refused by kata. _Avoid_: pipeline, recipe.

**Workflows Page**: The **Page** (`4`) that lists the Pane's Project's Workflows, archived ones hidden until asked for, with an inspector (Enter) that reads the selected one as steps with their dependencies and retries. Its state is Pane state that is not saved. It acts on the Pane's Project like the Board Page, and ends when the Collection is not a Project.

**Workflow card**: The Popup card `n` and `e` open on the Workflows Page. It holds the Workflow as the JSON text kata takes (`{"name": ..., "definition": {...}}`) in the Draft editor's text field, edited in the card or in `$EDITOR`. Saving checks the text locally against kata's rules first and keeps the text on any failure; the write is a Guarded write on the Workflow's `definition_event_uid`, and a conflict keeps the text beside the Workflow as it stands now. It saves any text kata accepts: under the text of a Workflow that passes kata's rules it draws the **Worker check**'s reading, which never blocks the save, and a text kata refuses shows only kata's problem.

**Worker check**: What this machine's **Worker** would refuse of a **Workflow** kata accepts, read by the Worker's own code (`worker.CheckWorkflow`: `options.on_fail`, `options.on_failure: "park"`, a profile on a command step, and a prompt budget over `max_run_prompts`; ADR-0008) and the same one its planning and `worker status` use. The Daemon gateway asks it and fills the budget from its own loading of `worker.toml`; the Pane model never imports the Worker. The **Workflow card** asks after a short pause as its text changes and at once when it opens on a Workflow or the text returns from `$EDITOR`, numbering each ask so an answer for older text is dropped; the **Workflows Page** inspector shows the reading for the stored Workflow, which arrives with the load and replaces itself on a save. When `worker.toml` is missing or does not load, the reading names the refusals that do not depend on it and says the prompt budget could not be checked and why; a missing file is not drawn as a warning. Unknown option keys are no refusal.

**Attention request**: A `notify.<address>` metadata slot on an open Issue, addressed to one **Inbox address**. It is either a request (no kind) or a reply notice (a kind: reply, confirm, refute or supersede), may be marked broadcast, and may name a comment (`re`). One model-level reader, `ReadNotificationSlot`, turns a slot into one, and the Activity wording for notification lines uses the same reader: `from` and `message` must be present and not blank, and a malformed optional field (`teammate`, `re`, `kind`, `broadcast`) is dropped instead of failing the slot. A comment's handle is `c:` and the last six characters of its ULID in lower case, as kata prints it. _Avoid_: inbox request, notification (for the thing the Page lists).

**Inbox address**: The exact address whose Attention requests the Pane reads: `KATA_INBOX_USER` when set and not blank, otherwise the Pane's actor, read at launch and trimmed. It must pass kata's recipient rules (not blank, at most 128 bytes, valid UTF-8, no control or format characters); when it does not, the **Attention Page** shows the reason and reads nothing. _Avoid_: inbox (the Collection keeps that word), recipient.

**Attention Page**: The **Page** (`6`) that lists every **Attention request** for the Pane's **Inbox address** across all Projects on the daemon, newest Issue update first, as one full-width list. Each row shows `project#short`, the title, the sender (`actor` or `actor/teammate`), a tag ("request", the reply kind or "broadcast"), the comment handle when the request names a comment, and the first line of the message; the selected row shows the whole message wrapped. The header reads "for <address> · N requests", plus "· M skipped" for slots that did not read. It acts on no Project, and its selection is kept by Issue uid across reads. Enter opens the Issue on the Issues Page with its detail focused, for an Issue of any Project, `m` opens the **Message card** for the agent behind the selected request, and `ctrl+r` reads again. Its state is Pane state that is not saved. _Avoid_: Inbox (the Collection).

**Graph order**: How the nested Issue list orders the children of one parent: creation order (the default), or blocking order, a topological order by the Collection snapshot's `blocks` links among the siblings with blockers first, where creation order breaks ties and cycles. `o` switches between them; the setting is Pane state and is not saved.

**agent.toml**: The file in tern-kata's config folder, beside `lanes.toml`, that says how an agent on an Issue starts: an optional `actor`, an optional top-level `host` (the name other machines show for this one; default the machine's host name; never per Project), an optional `name` (the teammate an agent's Attention requests carry; default the command's program name), an optional `command` argv (default `["omp"]`), and `[projects.<name>]` tables with `actor`, `name`, `command` and an absolute `checkout` that override the top-level values, and an optional `forward_comments` (top level or per Project; when true, a person's comments on the agent's Issue are delivered to the agent) and an optional `message_from` (top level or per Project; a list of actors, besides the agent's own, whose messages the agent acts on; they count only on a daemon in identity mode). It is decoded strictly and read on every start. It is written by hand or through the **Config Page**'s `e`, which opens it in `$VISUAL` or `$EDITOR` (from a commented starter when there is no file) and checks the result with the rules an agent start uses before writing it, only if the file did not change meanwhile; a file that does not parse or validate refuses the start and shows the error. The directory an agent starts in is the Binding's workspace, else the Project's `checkout` here, else the first checkout `worker.toml` lists for the Project, else a Notice that names `agent.toml`.

**Agent mapping**: `agents.json` in tern-kata's state folder: one entry per agent a Pane on this host started, holding the Issue's uid and qualified ref, the agent's block id and start time, its prompt file, the starting Pane's block id, the agent's `teammate` name (the name its Attention requests carry), its **Agent address** or why it has none (not omp), its `message_from` actors, and whether it belongs in the background and is open. Every Pane on the host shares it, it survives a Pane restart, and each change re-reads it first. An entry and its prompt file go when `tern ls --json` no longer lists the block, checked at Pane start.

**Agent address**: The **Inbox address** of one omp agent the Pane started, `<actor>/<agent.toml name>-<block id>` (for example `dana/omp-18494129176579`), the actor being the Pane's (on a daemon in identity mode, the account the daemon records for the Pane's credential, as every message from the Pane is written). `tern-kata agent` sets it as the agent's `KATA_INBOX_USER` from the block id in `TERN_PANE`, and tern-kata's omp extension in the agent delivers each request written to it as a message, at once, when its sender is that actor or, on a daemon in identity mode, one of the agent's `message_from` actors, and the event that wrote it was by that sender. It is unique to the block, so no other agent reads it, and it names the agent in `kata inbox` output. When the agent exits or its block goes, whatever is left there is cleared: by the Pane that started it, or by the next Pane to start when no Pane of that host was open. _Avoid_: agent inbox, mailbox.

**Agent record**: The metadata key `tern-kata.agent.<host id>-<block id>` on an agent's Issue, written by the Pane that started the agent so Panes on other hosts can find it: `{address, host, host_id, block, name, actor, started_at, no_address, message_from}`. Every mapped agent has one, omp or not (a non-omp agent carries its `no_address` reason). It is static, with no state and no heartbeat: written right after the **Agent mapping** records the agent, removed wherever the entry goes (the agent exits or its block closes, a stop, a **Background agent** ending, a reconcile), written again by a reconcile for an agent that has none, and removed by a reconcile when it carries this host's **Host id** and has no entry. A record of another Host id is never removed, and an agent whose **Agent address** a record of another host already holds publishes none and says so on its entry. See ADR-0018. _Avoid_: agent heartbeat, presence.

**Host id**: A random id made once and kept in `host-id` in tern-kata's state folder, which goes into every **Agent record** key and value and is what reconcile matches on. The host name beside it (`host` at the top level of `agent.toml`, default the machine's host name) is a label for the card; two machines with the same host name keep separate ids, so neither deletes the other's records. See ADR-0018. _Avoid_: machine id, hostname as identity.

**Blocker notice**: The message tern-kata's omp extension hands an agent when an Issue that blocks the agent's Issue closes: "<blocker ref> closed: <title>. <ref> may be unblocked.", with how many other blockers are still open. Unlike a message to the **Agent address**, no slot is written: the extension reads the Issue's blocking links at start and when they change, and reacts to the `issue.closed` events of its own Project's stream that happen after it started (once per event id after a restart). Parent and related links, and blockers in another Project, send nothing. See ADR-0015. _Avoid_: unblock alert.

**Background agent**: An agent started with `g` on the **Agent card**, whose block lives in a tab of the hidden Tern session called "kata agents" (made by the first one) and is named after its Issue. Its **Agent mapping** entry is marked `background`, and `open` while it is out of the hidden session. It is opened only by the user's act: a click on its **Agent badge** moves its block right of the kata Pane, and so does focusing it in the hidden session, which is what Tern's notification for an agent waiting for you does (the plugin's window half moves it beside the kata Pane named in its prompt file, else the one it focused last, else its only one). The Pane that started it sees from the window half's relay where the agent is and keeps `open` in step, also when the user moved it by hand. When an open one works again after it waited for you, the Pane that started it moves it back and clears `open`; one that goes idle or exits while open stays. A background one that is not open ends by itself: once its Issue is closed and the relay shows it idle or exited, the Pane that started it closes its block with `tern close` and removes its entry and prompt file (a failing close leaves the entry and shows a Notice); agents in a split or tab are never closed this way. _Avoid_: hidden agent, parked agent (Tern's parked deck is not used).

**Agent badge**: The marker that shows the state of the agents on an Issue: "agent working" (accent), "agent waiting for you" (warning), "agent idle" or "agent exited" (muted), or "agent" (muted) while no relayed state matches the agent's block. With several agents it names the most pressing one (waiting, working, idle, exited, none; the newest start on a tie) and adds " · N" for the N agents of the Issue. While the slot at the **Agent address** of an agent of the Issue holds a message the agent has not cleared (read from the Issue's metadata the Pane already loaded), it appends " · message unread" and takes the warning tone, as in "agent working · message unread"; the **Agent card** row says "message unread: " and the message's first line. It goes when the slot clears or the agent exits. It sits on the list and Lane rows (text, not clickable), on the Board card and in the Issue detail (a click runs `tern focus` on the agent it names), also on a closed Issue. _Avoid_: agent status, agent tag.

**Agent card**: The **Popup card** that `w` opens on the selected Issue, with or without agents; a closed Issue refuses `w` and opens none. It lists the Issue's agents, each with its state in the **Agent badge**'s words, its start time and where it is (split, tab, background or open; an agent mapped before the placement was kept reads as a split), or says in one muted line that there are none. Below the list it shows the selected omp agent's model, tool calls, current tool (the last tool call with no result after it) and cost, from the end of its session file (at most the last 1 MiB; a longer file marks the count "at least" and the cost `~`), and the first line of its last message from the relay; a non-omp agent, an agent whose session file is not named or does not exist yet, shows a muted reason instead. The Pane reads when the card opens and every 2 seconds while it stays open, and not while it is closed, and asks only about omp agents. The path comes from a file beside the agent's prompt file (`<prompt file>.session`) that tern-kata's omp extension writes on session start, switch and branch and, when it changed, on each agent start (omp's `/move` renames the session file without an event of its own). `s` starts a new agent in a split right of the kata Pane, `t` in a new tab and `g` in the background (a **Background agent**), each closing the card; `enter` goes to the selected agent (`tern focus`, or opens a background agent beside the Pane; `j`/`k` or the arrows move), `b` sends the selected agent to the background (a background agent that is not open stays there, with a Notice), `i` interrupts the selected agent's current turn (it keeps its block and conversation, and its badge reads idle once the turn ends; the Pane types Escape into the agent's block with `tern send`, since omp keeps a turn running on ctrl+c; the card stays open for `m` or `x`), `m` opens the **Message card** for the selected agent wherever its block is and `r` opens the quick-reply picker for it (each closes the card), and `x` asks, naming the agent and saying unsaved work is dropped, and on `y` stops it: `tern close` on its block, then its **Agent mapping** entry and prompt file go, and the Issue gets the full hand-off of an agent that exits while it is open: the request "agent exited without closing <ref>", `work.attention` `needs-human` with a reason in `work.attention_msg`, and `ready-for-agent` swapped for `ready-for-human` when it has it. Interrupt is off, with the reason as a Notice and a tooltip, for an agent that is not omp; both are off for an exited agent. `m` and `r` are off, with the **Message card**'s reason as a Notice and a tooltip, for an exited agent, an agent that is not omp, one started before agents had an address, and one another actor started. Stop works on a split, a tab or a Background agent, and any Pane on this host may stop any mapped agent (it reads `agents.json` again first); the automatic close of a Background agent stays with the Pane that started it. `esc` cancels. `enter`, `b`, `i`, `m`, `r` and `x` do nothing without agents. Only ctrl+c passes through it. _Avoid_: agent list, agent picker.

**Team**: One **Coordinator** agent on a parent Issue and a queue of **Background agents** on its ready children, at most the limit (1 to 8, default 2) running at once, started by `c` on the parent's **Agent card** and recorded in `teams.json` in tern-kata's state folder, beside the **Agent mapping**. Its state is `running`, `paused` (starts nothing and never ends by itself), `stopping` (the coordinator exited: nothing new starts and the record goes once no child runs) or `ending` (the end message waits for the coordinator's unread message to clear). Any Pane on the host whose actor started the team drives the queue on each agent relay and each event (a Pane under another actor leaves it alone, but retires a stopping team): the next child is the first of kata's ready, unowned Issues that is a child of the parent in its Project, that the team has not started before and that has no running agent; an open child that another host's **Agent record** holds is neither started nor done, so the team does not end while it stands. When no child is left to start and none runs, the Pane writes one message to the coordinator, from the person, naming the children closed and still open, and the record goes. _Avoid_: swarm, crew.

**Coordinator**: The agent a **Team** starts on its parent Issue, with `TERN_KATA_COORDINATING=1`. Its messages to its own children carry the person's authority over the child's Issue, which a child recognises by `TERN_KATA_COORDINATOR` (the coordinator's **Agent address**) set when it started; it directs nothing on another Issue, never overrides the child's acceptance criteria or the person's explicit instructions, and it alone asks the person. The teammate that marks its messages is advisory: any agent of the same actor can name it. A child keeps the coordinator it started with. _Avoid_: manager, lead.

**Message card**: The **Popup card** that `m` opens on the **Attention Page** for the agent behind the selected request, or on the **Agent card** for the selected agent, or on the Comments tab of the Issue detail for a comment, naming it and carrying its UID as `re` so the agent answers it with `kata comment --reply`, `--confirm`, `--refute` or `--supersede` (the Issue's own agent, the newest that waits, else the newest). From the Attention Page it is: of this host's agents on the request's Issue whose name the request carries, in a request the Pane's actor wrote, the newest that waits, else the newest. Its one field takes the message (at most 1024 bytes), written to the agent's **Agent address** on the Issue guarded on the address holding nothing; when the agent has not cleared its last message it shows that message and asks before replacing it. `r` on either page opens the quick-reply picker instead, where `1`, `2` or `3` sends a canned text through the same send. `S` on an Issue opens the card for every running agent on it and its open children: one write each, never replacing an unread message, then an outcome listing how many got it and each skipped agent with its reason. `m` and `r` open none, with the reason as a Notice, for an exited agent, an agent that is not omp, one started before agents had an address, one another actor started (the agent takes messages only from the actor in its address), and a request no agent raised. _Avoid_: chat, reply box.

**Update**: `tern-kata update`, or the **Update tern-kata** palette command, which runs it in a new Pane on the focused Pane's machine and then reinstalls the window plugin on the window's machine when that is another one. It brings the session host's binary to the latest release. It reads `version.txt` from the release (or from the folder `TERN_KATA_BASE_URL` names), says so when this binary is that version or newer (it never downgrades; it still updates this machine's installed copy of the window plugin), otherwise downloads the OS archive and `checksums.txt`, checks the archive's SHA-256 and swaps the running binary: on Unix a rename over it, on Windows the old file is renamed to `.old` (a `.old` still in use by a Pane or the Worker is renamed aside first). It then brings this machine's installed plugin copy to the new release (a linked copy is left as it is) and gives a Worker the plugin restarts an idle stop, so it returns as the new binary once its runs finish. It prints the new version, asks you to reopen tern-kata Panes and gives the agent skills' update command. Only a release build updates itself; a `go install` or source build gets the command for its kind of install. One update runs at a time (`update.lock` in the state folder), and `--pause` waits for Enter after a success so a Pane shows the result. Exit status 0 means the binary is at the latest version. _Avoid_: upgrade (`worker upgrade` is the Worker's trust grant).

**Release check**: The window plugin's daily look at `version.txt` in the latest release (or in `TERN_KATA_BASE_URL`), made at window start and every 24 hours while the window stays open, only when the last check kept in `tern.kv` (`os.time()`) is over 24 hours old. A newer release than the plugin's own version toasts "Run Update tern-kata from the palette" once per version; a failed request is silent and still counts as a check. The **Turn tern-kata update checks off/on** palette command or a non-empty `TERN_KATA_NO_UPDATE_CHECK` turns it off (the variable wins over the toggle), and a plugin linked with `tern plugin link` (its folder is not `<tern plugin dir>/tern-kata`) never checks.

**Pre-flight**: The check `tern-kata update` has the downloaded binary make of this machine before the swap: the old binary runs `tern-kata update --preflight` on the unpacked new one, with a 30-second limit. A contract between releases, which later ones may only add to: exit 0 when nothing is refused and 1 when something is, and stdout is JSON, `{"refusals":[{"kind":"kata"|"config","message":"…"}],"warnings":["…"]}`. A `kata` refusal is a daemon older than the new binary's `MinKataVersion` (a kata daemon that can't be reached, or does not answer within 10 seconds, is only a warning, and so is one older than kata v0.23.0, which attachments and search by meaning need); a `config` refusal is a `worker.toml` its `LoadConfig` rejects. Any other exit status, unreadable JSON, an unknown kind or a timeout counts as a refusal ("the new tern-kata could not check this machine: …"). Refusals stop the update before the swap unless `--force`, which prints them as warnings and remembers a forced refusal of either kind (`config`, or a pre-flight that could not check this machine), after which the Worker is left running with a note; warnings always print. The install scripts run `tern-kata update --preflight --text` on the binary they just installed, which prints each refusal and warning as a `warning: …` line, and install anyway; a release before `--text` prints nothing. _Avoid_: preflight check (as a name for the whole update), dry run.
