# Each run has one journal, written before its side effects, and recovery continues it

The worker keeps one JSON journal per run. Every transition, and every kata write the run still owes, is saved there before it happens. After a crash or restart the worker reads the journals, reconciles them with kata, and continues saved work; it never infers a new attempt from kata's run status, and a missing journal never permits a rerun.

herdr-kata's design (run-lifecycle.md, state.md, recovery.md) is adopted almost whole, because it was built around the same failure: a launched agent whose outcome the worker cannot see. What changes is the thing being proven.

## Decisions

- **One journal, one writer: adopt.** `runs/<run uid>/run.json` holds the frozen job and workflow definitions and event uids, input, target, profile, checkout, timeout, step and attempt states, hold and outcome, the generation, and the ordered kata intents with their payloads and guards. Each transition locks, reads the current file, applies, and replaces it durably (temp file, fsync, rename, directory fsync). Execution, control requests and report delivery all go through that path, so a late completion never overwrites newer state. Files are versioned and size-bounded. No separate outbox database.
- **Submission barrier: adapt.** herdr-kata saves `sending` before it types a prompt into Herdr and `accepted` after any reply. The equivalent is a `launching` mark saved before the worker starts omp, followed at once by a start record (pid, process group, kernel start time, session path) saved before the worker waits. A recovered `launching` with no start record is `launch_unproven`; a start record with no exit status is `interrupted` or `no_receipt` (ADR-0005). Commands use the same two records, as herdr-kata's `process.json` does.
- **Settlement proof: adapt.** herdr-kata proves an occupant settled with pane identity, a saved agent session and an advancing completion sequence. For a process the worker spawned the proof is its recorded exit status and an empty process group. The group is polled until gone; the kernel start time guards against a reused pid. On Linux the child is started with a parent-death signal so a killed worker leaves no running agent; elsewhere a killed worker may leave one, which the next start finds as `group_unproven` and waits out (ADR-0005).
- **Activity grace: reject.** herdr-kata waits up to 5 minutes for activity (`no_activity`), ignores idle/done unless the completion sequence advanced, and gives a result file ten seconds after settlement (`no_result`), because Herdr can report an agent idle before it has started or after a stale turn. A process that has exited has no stale state, and omp writes no result file (ADR-0009), so none of it applies. The carried-over rule is the one it protected: a valid report never advances work while its producer may still be running. Here nothing is read from a run until its process group is gone.
- **Reporting intents: adopt.** Each Issue write a run owes (per-run Issue create, observation, comment, label, close, notify) is journaled with its exact payload before it is sent, and retries reuse it. Safety classes carry over: replay-safe (observations; keyed create, comment and close within kata's seven-day key window), guarded (metadata with a saved revision or value), read-back (claim, notify: confirm the effect by reading, never blind-retry). A final observation never waits for an Issue write; observations keep revision order. Retired or unconfirmable writes mark the run `inspect` and surface in `worker doctor`.
- **Recovery order: adopt.** On start: take the lock, read the Project's lease (ADR-0003), reconstruct reservations from journals before preparing anything, check the route, reconcile prepared admissions (replay the saved observation), reconcile final observations that differ from kata (read back first; replay only if the stored run is still `running` at the frozen revision), then resume saved reporting. Nothing executes before reconciliation ends.
- **Quarantine: adopt.** A journal that cannot be read moves, whole, to `quarantine/runs/<run uid>/`. That directory vetoes preparation of the uid, so state damage cannot cause a rerun. It no longer reserves capacity; `worker doctor` reports it and `abandon` acknowledges it. Never delete one to unblock a job. *Acknowledgement* is an `acknowledged.json` marker (who, when) saved inside the folder: the folder and its veto stay, `worker doctor` lists it as a note instead of a problem and `worker status` stops nagging. When kata still shows the run running for this executor, `abandon` first records it `unknown` "local state lost" (ADR-0002) and comments on its Issue.
- **Retention: adopt.** A daily pass (once at start, then every 24 hours) removes settled, fully reported run directories whose end is older than 14 days, and retires each removed run's lock with it. Held, inspected and unreported runs stay, and so does a journal the pass cannot read (startup recovery owns quarantine).
- **Event cursor: adopt as a hint** (`projects/<project uid>/events.cursor`), never evidence (ADR-0004).
- **Scheduler checkpoint: adopt.** `projects/<project uid>/jobs/<job uid>.json` records the definition event uid, the handled-through instant and pending occurrences, replaced atomically. History never advances it; a definition change supersedes unadmitted pending work and prepared runs keep their frozen definitions. ADR-0011 owns the rules it serves.
- **Test seam: adopt.** herdr-kata names journal points (`launch-intent`, `result`, `create-result`, `resume-acceptance`, one per op result) and a `crashpoint` build tag that kills the worker at one of them. The spec's worker seam needs the same: a hook the test injects, called after each named journal save, kills the worker in process; the test then restarts it on the same state folder and asserts what kata holds. No build tag.
- **Supervisor/worker/serve split, staged binaries, plugin-ID migration, `up.lock`/`serve.lock`: reject.** One process with one `worker.lock`; the plugin host half or an OS service restarts it. There is no report binary to stage (ADR-0009) and no earlier layout to migrate.

## Consequences

- State lives in tern-kata's user state folder: `worker.lock`, the control socket, `projects/<uid>/{pin.json,events.cursor,jobs/}`, `runs/`, `quarantine/`. The spec's list gains the checkpoint, pin and quarantine entries.
- Run directories hold absolute paths to sessions and logs; moving the state folder needs the worker stopped and the old path kept while any held run refers to it.
- On Windows there is no process group to poll; the implementing ticket must use a Job Object for the same proof or refuse prompt and command steps there and say so in `worker status`.
