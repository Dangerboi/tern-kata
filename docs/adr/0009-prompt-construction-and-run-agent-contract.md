# The run agent is told its Issue and how to leave a record; the worker checks it did

A prompt step runs `omp -p --mode json` in the job's checkout. The prompt is the job's task text with context ahead of it and a short contract after it: which Issue this run is, to comment its result and close it with evidence, and to say what it did in its final message. When omp exits, the worker reads the Issue. If the agent did not close it, the worker posts the final message as a comment and labels the Issue `needs-review`.

herdr-kata (agent-contract.md, reporting.md, prompts.md, the golden prompts in `internal/runner/testdata`) has the agent write an attempt-bound `result.json` through a staged `report` binary, and the runtime does all kata writes and closes. That contract exists because Herdr cannot tell when an interactive agent is done and the runtime must not give the agent credentials. Neither holds here.

## Decisions

- **Invocation: adapt.** `omp -p --mode json --session-dir <run dir> [--resume <session id>] [--model M] [--thinking T] --approval-mode yolo [profile args]`, `cwd` the checkout (or the run directory when the job names none), the prompt as one positional argument or an `@file` (the 256 KiB bound is enforced either way; several positionals would be several turns). **stdin is `/dev/null`**: without a TTY omp reads stdin to EOF as prompt text, and an open silent pipe blocks it [live]. One process per attempt; its end is the end of the step. Success is exit 0 **and** a terminal `agent_end` whose last assistant message has `stopReason: "stop"`; no `agent_end` is a failure whatever the exit code. Exit codes seen: 0, 1 (model or session not found, provider error, `--max-time`), 2 (usage error), 143 (SIGTERM, with no `session_exit` record in the session file). The worker enforces its own timeout and does not pass `--max-time`. How omp behaves unattended without an approval flag was not observed, so the worker passes an explicit `--approval-mode yolo` unless the profile's `args` set `--approval-mode` or `--auto-approve` themselves; a served Project is trusted (spec), so this adds no exposure. `--restore` and `--continue` are not usable headless (ADR-0005). omp writes its own global state (history, memory) even with `--session-dir`; a profile may add `--profile <name>` to isolate it.
- **Prompt contents: adopt, trimmed.** In order: the run's Issue (qualified ref, title, body for a per-run Issue), job name, run uid, occurrence, step and attempt; for a workflow, its name and `about`; the task text; the contract. herdr-kata's report command, result path and the staged binary are dropped. Attempts after a retry or a resume add the failure and the partial-work warning (ADR-0008). Bounds: the expanded prompt at most 256 KiB, UTF-8, no NUL; over that holds `invalid_prompt`.
- **Contract text: adapt.** Tells the agent: this run's Issue ref; that it is acting as the executor's actor; to comment what it did and how it verified it; when the work is done and verified, to close the Issue with `kata close <ref> --done -m "<what was done and how it was verified>"` plus evidence (`--commit`, `--pr`, `--test`, `--reviewed`, or `--audit-no-change --evidence no-change-audit:<what was checked>`); not to close it otherwise; to say plainly in its final message when the task failed or needs a person; never to pad or invent evidence. For an existing-Issue job: comment only, never close. kata's own `close` already validates evidence types and the message length (at least 40 characters for `done`), so herdr-kata's local close validator is not needed: a refused close reaches the agent, which fixes it. The final message becomes the run summary.
- **Who writes: reject herdr-kata's rule.** herdr-kata keeps kata credentials from agents and lets only the runtime write. The agent runs as the same OS user with a shell and the worker's files readable, so withholding the credential protects nothing; the agent needs the `kata` CLI anyway (spec stories 70, 86). The child environment is the worker's, minus `TERN_KATA_*` internals, plus `KATA_AUTHOR=<actor>` and the routing and credential variables kata's CLI needs to reach the same daemon. herdr-kata's strict allowlist for kata children and its clean-environment probe (`herdr_env_unclean`) are rejected with the pane.
- **Closure check: adapt.** After exit 0 the worker reads the Issue. Closed: done. Open: comment with the final message (key `tern-kata:<run>:comment:succeeded`), label `needs-review` (kata's own convention for unfinished work), and record `succeeded` (herdr-kata's "success without usable closure evidence": the run succeeded, the result needs a reader). Nonzero exit or timeout: `failed`, comment with the reason (key `...:comment:failed`), the Issue left open. Held: ADR-0005. Existing Issues get a comment in every case and are never closed or labelled. herdr-kata's quiet success for all-command workflows is adopted: no comment when every step is a command, every command exited 0 and the Issue is existing; the final observation still carries the receipt message.
- **Attention metadata: reject.** herdr-kata sets `work.attention` and `work.attention_msg` with revision guards to mark stuck or needs-human. The label and comment give a reader the same signal without a guarded write per transition; held runs notify (ADR-0005).
- **Summary and tokens: adapt, shape settled.** From the JSON stream [live, notes §1.3]: the session id is the first `session` event's `id` (the session file is `<run dir>/*_<id>.jsonl`; its path is in no event); the final message is the last assistant message of the last `agent_end` with `isTerminal` absent or true (`false` means omp continues, keep reading), its `text` content items joined, other content types skipped; usage is `usage.{input,output,cacheRead,cacheWrite,totalTokens,cost.total}` on each assistant `message_end`, summed across the run's assistant messages (after `--resume` `agent_end` holds only the new ones, so attempts are summed from the journal). The observation's `message` is the final message, truncated to kata's 64 KiB summary bound with the failure or uncertainty reason kept first. `input_tokens` is `input + cacheRead + cacheWrite` and `output_tokens` is `output`, as herdr-kata counts prompt tokens; both are left empty when any attempt lacks usage (a provider error reports zeros). The dollar cost is not reported to kata.
- **Secrets: adopt.** `secret_refs` maps environment names to `[secrets]` names (ADR-0010). Values are read at each step, supplied only to the child, and never written to kata or the journal. A missing or unreadable source holds `secret_unavailable` before the step starts. Names `KATA_*` and `TERN_KATA_*` are reserved and refused.
- **Agent quota and login classification: adopt** from `stopReason: "error"` and `errorStatus` (ADR-0005).
- **Steering mid-turn, tab or pane per run: reject.** No window exists. `o` on the Runs page opens `omp --resume <session>` in a new Tern tab for a finished or held run (spec).

## Consequences

- A weak agent can close an Issue with thin evidence; kata checks the shape, not the truth, as herdr-kata notes of its own validator. The skill's wording and the `needs-review` fallback are the guard, as the spec's trust statement implies.
- The worker's prompt is tested as text: a golden prompt per kind of run (prompt job, workflow step, existing Issue, retry, resume), as herdr-kata does.
