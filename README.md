# tern-kata

Native kata Issues in a Tern Pane. Requires Go 1.27+, kata v0.18.0+ on `PATH`, and Tern with Surface Protocol support. Without Tern support, compatible arguments pass to `kata tui`; `--as` becomes `KATA_AUTHOR` because kata's TUI ignores the flag, and `--issue <project>/<short_id>` becomes kata's equivalent qualified Issue argument.

```sh
CGO_ENABLED=0 go build -o tern-kata .
CGO_ENABLED=0 go install github.com/Dangerboi/tern-kata@latest
CGO_ENABLED=0 go test ./...
./smoke/run.sh
```

Run `tern-kata` inside Tern in a directory bound with `kata init`: it opens that Project's Issue list straight away, without the Collections sidebar. Use `j`/`k` or `↓`/`↑`, `g`/`G` or `home`/`end`, and `q`/`ctrl+c`; the same keys move through the Issue list, Collections and Issue detail references, and `p` opens the **Collections picker**. Press `?` for all bindings with their modes; `?` or `esc` closes help without moving the selected Issue. The dock shows only current-mode hints, and the help layer lists every binding, both from `model/keymap.go`.

Daemon discovery uses `kata daemon locate --json`. Local daemons resolve the workspace on their own filesystem. For remote daemons, tern-kata reads the client-side `.kata.toml`, stopping at the nearest Git root, and sends the bound Project name plus an available Git or local alias instead of a daemon-side `start_path`. An alias can select the canonical Project after a rename. Unbound directories open Inbox with the Collections sidebar; malformed bindings and missing remote bound Projects show errors, including the daemon's recovery hint. Each command releases its Unix HTTP transport's idle connections, including failed discovery.

Install `kata` and `tern-kata` on the session host, the machine whose shells run in your Panes, with `tern-kata` on that shell's `PATH`. Install the window plugin on the machine showing the Tern window: Tern runs window halves only from the window machine's plugins folder, and a remote host's window halves never run in your windows ([Tern distribution guide](https://docs.stencil.so/tern/guides/distribution.html#remote-hosts)). `tern plugin list` showing `window ready` on the session host therefore does not reach a remote window. For a local window, both are one machine: `tern plugin link .`. For a remote window, run `tern plugin install github.com/Dangerboi/tern-kata` on the window machine. The repository is private and Tern clones with terminal prompts off, so that machine needs non-interactive GitHub access: a credential helper (Git Credential Manager, or `gh auth setup-git`), or `tern plugin install git@github.com:Dangerboi/tern-kata.git` with a loaded SSH key, or your own clone installed with `tern plugin install <dir>`. The window machine needs no Go, kata or tern-kata.

**Open kata** in the palette, or `F9`, opens a right split in the focused Pane's directory. A literal `kata://<project>/<short_id>` link focuses a running kata Pane and selects the Issue without restarting it, or opens a split with `tern-kata --issue <project>/<short_id>`. Links may select closed or other-Project Issues in detail without changing the current Collection. Percent-encoded segments, query strings and fragments are declined. Missing `tern-kata` on the Pane's `PATH` prints `go install github.com/Dangerboi/tern-kata@latest` in the Pane. OS scheme registration is separate; the plugin handles links delivered inside Tern.

The plugin sends a TSP `action` to `main.columns.list.issues` with `act: "select-issue"` and `value: "<project>/<short_id>"`. The binary uses the same model message path for startup selection and this action; its terminal title `tern-kata` lets a reloaded window plugin discover an existing Pane.

Tern 0.6.2 (`4b3ed42`) performs synchronous login-environment capture when a plugin uses `Launch.command`. A minimal hook containing only `cx.layout:split(cx.session:focused(), "right", {command = "exec /bin/sh"})` reproduced a 57.95 ms capture, the warning `plugin="bare-split" hook="command open" error=runtime error: tern: command open exceeded 50 ms`, and a skipped second launch: the Pane count stayed at two. The shipped Launch fields and runtime preferences expose no per-launch capture switch.

The launcher instead opens a default shell split in the target's directory and checks `PATH` directly in that Pane with `cx:run`, executing `tern-kata` or printing the install hint. It uses neither a timer nor `Launch.command`. A minimal split-plus-run hook produced its output on two consecutive launches without reload, in distinct Panes. The plugin smoke attempts consecutive palette/key launches without reloading and rejects hook-budget warnings; real OSC-8 links also open and reuse a Pane in that same plugin session.

Selecting an Issue loads its Markdown body, properties, labels, links, comments and change history beside the list. `enter` opens detail, `esc` or `←` returns to the list (then the Collections picker, or the Collections sidebar in an unbound directory), `tab`/`shift+tab` cycle detail sections, and `enter` follows the selected referenced Issue; `esc` unwinds those jumps. `L` hides or restores detail. Panes narrower than 100 columns show only the focused column.

Loading never blanks the Pane: only the very first load shows a full-Pane message. Later, switching Collection keeps the previous list under a muted `loading…` marker in the list heading, and selecting another Issue keeps the previous detail under the same marker in its heading, until the new content replaces it in place. Element keys are fixed per Issue, detail section and row, so Tern keeps native scroll. Clicking an Issue row does not reveal or scroll the list. Detail goes back to its first section only when a different Issue arrives; a refresh of the same Issue leaves the reader where they were.

Page Up/Page Down scroll the focused Collections, Issue list or detail column by a native Tern page; in search they enter the results before scrolling. Footer hints are clickable and use the same keymap dispatch as their displayed keys. Form hints only show bindings handled by that form. Link labels describe the relation from the selected Issue: incoming parent links show children, and incoming blocking links show `blocked_by`.

Press `e` to edit the selected Issue body, or `c` in detail to add a comment. The native editor keeps UTF-16 caret/selection offsets and an application undo stack (`ctrl+z`); `ctrl+o` saves. Non-empty Drafts ask before `esc` discards them. Drafts are keyed by Issue UID and keep their original revision through live refreshes. Revision conflicts show your Draft beside the current body: `o` retries against that version, and `d` discards only your Draft. Saves fetch and compare the Issue revision first: kata v0.18.0 ignores body PATCH `If-Match`, so the check-then-write race remains until upstream enforces it.

`ctrl+e` opens the Draft in `$EDITOR` via a private temporary Markdown file. The app stops its input reader and closes the Tern Session (restoring tty/raw mode), runs the editor with the real stdin/stdout/stderr, then reconnects and restores the in-memory Draft. `Suspend` alone is not sufficient because it does not release stdin. Successful external edits return to the Draft, not directly to kata; use `ctrl+o` to save. Editor errors keep the original Draft.

Tern 0.6.2's Linux headless runner sends `meta+o`, `meta+e`, and `meta+z` for the corresponding `Ctrl` harness chords. Both the intended `ctrl` and observed `meta` variants are bindings; the headless smoke exercises the actual Tern mapping. Desktop modifier mapping is not independently verified.
In the list or detail, `+` adds a label, `-` removes one, `a` assigns an owner, `A` clears the owner, and `!` sets priority. Prompts save with `enter` (or `ctrl+o`/`ctrl+s`) and cancel with `esc`; priority accepts 0-4 or `-` to clear. Labels complete with up/down and tab using project labels for addition and attached labels for removal. Rejected writes keep the prompt and kata's error visible. Writes use `--as <actor>`, then `KATA_AUTHOR`, `USER`, git user.name, or anonymous, in that order; authenticated kata identities retain authority over the requested actor.

`n` opens a create Draft; `N` creates a child of the selected Issue with its parent link included in the create request. Tab/shift+tab moves through title, native body editor, comma-separated labels, owner and optional priority (0-4). Up/down chooses a label suggestion and ctrl+space completes it. Ctrl+o creates; Escape confirms discard for non-empty Drafts. Project Collections create in that Project; other Collections use the selected Issue's Project, or the bound Project if nothing is selected. Child creation always uses its parent's Project. Without either Project, creation reports an error. Rejections retain the Draft and kata's error. The returned UID stays selected through refresh, and the parent expands to expose a created child.
If a created Issue is excluded from the current Collection, its pending selection ends when you explicitly navigate or select another Issue or Collection.
Issue rows show short id, title, status, priority, owner and labels. Nested lists start collapsed: `space` toggles the selected parent's children, `→`/`←` expands/collapses, `E` toggles every parent, and `v` switches flat/nested (returning to nested collapses all). Expansion follows Issue UIDs across refreshes; collapsing moves a hidden selection to its nearest visible ancestor. Priority 0 uses the host's error tone, and closed Issues use its muted tone.
A click takes the same state change as the keys that reach the same place, from any column. A row click gives the list the keys with that row selected; on a parent row it also expands or collapses the children, even from the sidebar or detail. A Collection click (a sidebar item in an unbound directory, a picker row in a bound one) switches as `enter` does, a detail heading or row click gives detail the keys on that section, and Open referenced Issue jumps as `enter` does. So `esc` backs out the same way after a click as after the keys: each jump unwinds one Issue, and jump history belongs to the detail column, so leaving it by any key or click (a row, a Collection, the list heading) ends it and `esc` never replays an earlier jump. Clicks inside a layer (filters, create, close, the label prompt, help, search) leave `esc` closing that layer.
Collections (Inbox, Today, Upcoming, Deadlines, All Open, Logbook and every Project) load from the daemon UI snapshot. A directory bound to a Project has no sidebar; `p`, a click on the list heading, or `esc` from the Issue list opens the **Collections picker**, a popup inside the Pane listing the same Collections with the bound Project pinned first and the current Collection marked `current`. Typing filters titles in any case. `↓`/`↑`/`home`/`end` move, and `j`/`k` move while the filter is empty and are typed once it has text; `enter` or a click switches, and `esc` closes the picker without changing anything. After a switch the list heading names the new Collection and the bound Project is the picker's first entry. Unbound directories open Inbox with the sidebar as a third column: press `esc` from the Issue list to focus it, navigate with `j`/`k`/`↓`/`↑` or `g`/`G`/`home`/`end`, and press `enter` to switch; sidebar items are also clickable. Date headings match kata's web UI: literal calendar dates for Upcoming and Logbook, Overdue/Today for due work, with today's evening Issues merged into Today. Snapshot requests include the local calendar date and IANA time zone and reuse ETags only for the same Collection intent.

`/` searches the current Collection through the daemon snapshot as you type. Up/down moves through live results; `enter` first focuses results and then commits the search. In results, `esc` or `/` returns to the query; query `esc` restores the previous search and selected Issue. `s` cycles all/open/closed without a ready state. `f` opens Project, status, owner, label and relationship filters: tab/shift+tab changes fields, left/right or space cycles choices, and ctrl+o (or ctrl+s) applies; Escape cancels. Owner matches exactly, comma-separated labels match any label, and relationships are Has parent, Has child, Blocks, Blocked by or Related. All axes combine, remain visible in the list header, and survive event refreshes and Collection changes. Project filters cannot widen a Project Collection. `c` clears every filter and restores the Collection's default status; explicit all status includes both open and closed results. The form also has Apply filters and Cancel buttons.

Press `x` in the Issue list or detail to open the close form. Use `tab`/`shift+tab` to select a field, `ctrl+u` to clear it, `ctrl+o` to submit, or `esc` to cancel. Commit SHA, PR URL and test command evidence are optional fields, but normal `done` requires at least one; duplicate/superseded and audit reasons have dedicated reference/rationale fields. **Quick done** (`ctrl+d`) sends the owner-local interactive exemption, not fabricated evidence. The daemon still enforces parent-close and throttle guards. Close uses the loaded revision and `close-v1`; conflict, guard and throttle messages remain readable in the form. Press `r` to reopen.

The smoke runner needs `kata`, `tern`, `jq`, `git` and `python3` on `PATH`. It isolates both instances, seeds three open Issues in Project `smoke`, and runs `smoke/steps/*` in filename order: `.ctl` scenarios or sourced `.sh` assertions using `ctl` and `expect_tree`. Add a step file for each feature; leave the app in the Issue list for the next step. Use `plugins expect` for native text, but `expect_tree` for list labels (Tern's text search excludes them). Failed runs retain their temporary artifacts and exit non-zero. The seeded workspace is bound, so kata starts project-first without the sidebar; steps switch Collections through the picker (`p`, then a `layer.collections.list.<key>` row). The picker step also launches kata in an unbound directory to see the sidebar and resizes the window to check narrow folding.
Each write scenario should create its own fixtures and select mutation targets by Issue UID. Steps share a Project, but must not depend on the selection left by an earlier step or mutate another step's fixtures.
The remote-binding step forwards requests to the real throwaway daemon through a recording proxy, checking Name/Alias resolution without `start_path`, the selected Project UID, and readable daemon Message/Hint errors. The suite also clicks the help footer hint, then runs `smoke/plugin.sh` against the built binary for consecutive palette/key launches without reload, real OSC-8 links and the missing-binary in-Pane hint.
The esc-after-click step (`smoke/steps/09-abhr-esc-after-click.sh`) clicks a parent row from the sidebar, a nested child, a referenced Issue, a Collection mid-jump, a detail heading, and inside the filter, create, close, label-prompt, help and search layers, and requires `esc` to back out each time. It runs in an unbound directory so the sidebar is there to click. It guards two regressions: a parent row clicked while the keys sit in the sidebar or detail must take them to the list, and a Collection clicked mid-jump must end the jump.
`07-jvgq-stable` launches the app with `TERN_TSP_RECORD=<file>` and asserts on the TSP ops it recorded: nothing may delete and re-add a column or the detail's title and sections, or reveal a clicked row. Polling the tree cannot prove that, because the daemon answers faster than a poll sees. It uses an unbound directory so the Collections sidebar is there to click.
To run only the editor slice: `./smoke/run.sh smoke/steps/01-spyn-tree.sh smoke/steps/06-x2b9-editor.sh`. Its interactive shell-editor fixture reads stdin and appends to the temporary Draft, exercising tty ownership and reconnection rather than an unattended file rewrite.

Launch commands in smoke steps through a `.ctl` file containing `run "<command>"`; passing an unquoted command argument directly to `tern ctl run` loses the headless runner's required script quoting.

Views use Tern's native typography, spacing and selection accent for readable Issue rows, following the host theme without a palette or added animation (energy/rhythm/motion 1/1/1). Model Msg/Cmd values are extended in per-feature files; `model/keymap.go` remains the single source for key handling and hints.
`view/render_test.go` is the `view.Render` seam: build a Model with `model.Update`, render it through the SDK's reconciler, and check the nodes by the ids Tern derives from their keys (`render`, `text`, `sameIDs`).
Caret focus uses one rendered-input target across forms and search. Tern's queued focus/reveal operations can outlive a transient node when renders coalesce; unknown-target rejections for those known transient nodes retain model state instead of exiting the Pane. Smoke daemon restarts wait for the old instance to finish stopping before starting a replacement.

Issue lists refresh from kata's durable event stream, resuming after the last applied snapshot cursor. A history reset refetches the complete Collection. Live merges keep Issue UIDs and selection stable so Tern retains native list scroll; they do not reveal the selection again. Disconnected streams keep stale Issues visible read-only while reconnecting with capped exponential backoff. An unreachable daemon shows kata's message and a clickable **Retry daemon** button (`ctrl+r`).
Live refreshes also request the selected Issue's authority and change history, preserving the same Issue's detail section, reference index and native scroll position.
