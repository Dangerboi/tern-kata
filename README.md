# tern-kata

Native kata Issues in a Tern Pane. Requires Go 1.27+, kata v0.18.0+ on `PATH`, and Tern with Surface Protocol support. Without Tern support, compatible arguments pass to `kata tui`; `--as` becomes `KATA_AUTHOR` because kata's TUI ignores the flag, and `--issue <project>/<short_id>` becomes kata's equivalent qualified Issue argument.

```sh
CGO_ENABLED=0 go build -o tern-kata .
CGO_ENABLED=0 go install github.com/Dangerboi/tern-kata@latest
CGO_ENABLED=0 go test ./...
./smoke/run.sh
```

Release builds and the normal test run stay pure Go (`CGO_ENABLED=0`). The race detector needs cgo, so run it only on a dev machine: `CGO_ENABLED=1 go test -race ./...`. With cgo on, kata's dependencies build C SQLite, which needs its headers once (`sudo apt install libsqlite3-dev` on Debian/Ubuntu); without them the `data` and root packages fail with `sqlite3.h: No such file or directory`.

Run `tern-kata` inside Tern in a directory bound with `kata init`: it opens that Project's Issue list straight away, without the Menu sidebar. Use `j`/`k` or `↓`/`↑`, `g`/`G` or `home`/`end`, and `q`/`ctrl+c`; the same keys move through the Issue list and the Menu, `j`/`k`/`g`/`G`/`home`/`end` move through the Issue detail's references while `↓`/`↑` and `pgdn`/`pgup` scroll the detail, and `p` opens the **Menu**. Press `?` for all bindings as a sheet that fills the Pane in place of the top bar, filter line, columns and footer hints: the title `tern-kata — keybindings`, kata's own help groups in kata's order (Global, Graph, Detail, Children, Forms, Filters) in a wrapping row of columns, with kata's wording and only the entries tern-kata binds, each a title over `key  action` lines with the keys padded to the group's longest key, and `press ? to return` at the bottom; the mouse wheel scrolls it. Keys come from `model/keymap.go` (joined by `/` when several share an entry); an entry whose binding is removed drops out, and Tern-headless-only chords are left out. `?` or `esc` closes it without moving the selected Issue. The dock shows only current-mode hints, and the help sheet lists kata's entries that the keymap binds.

Daemon discovery uses `kata daemon locate --json`. Local daemons resolve the workspace on their own filesystem. For remote daemons, tern-kata reads the client-side `.kata.toml`, stopping at the nearest Git root, and sends the bound Project name plus an available Git or local alias instead of a daemon-side `start_path`. An alias can select the canonical Project after a rename. Unbound directories open Inbox with the Menu sidebar, which goes once a Project is entered; malformed bindings and missing remote bound Projects show errors, including the daemon's recovery hint. Each command releases its Unix HTTP transport's idle connections, including failed discovery.

Install `kata` and `tern-kata` on the session host, the machine whose shells run in your Panes, with `tern-kata` on that shell's `PATH`. Install the window plugin on the machine showing the Tern window: Tern runs window halves only from the window machine's plugins folder, and a remote host's window halves never run in your windows ([Tern distribution guide](https://docs.stencil.so/tern/guides/distribution.html#remote-hosts)). `tern plugin list` showing `window ready` on the session host therefore does not reach a remote window. For a local window, both are one machine: `tern plugin link .`. For a remote window, run `tern plugin install github.com/Dangerboi/tern-kata` on the window machine. The repository is private and Tern clones with terminal prompts off, so that machine needs non-interactive GitHub access: a credential helper (Git Credential Manager, or `gh auth setup-git`), or `tern plugin install git@github.com:Dangerboi/tern-kata.git` with a loaded SSH key, or your own clone installed with `tern plugin install <dir>`. The window machine needs no Go, kata or tern-kata.

**Open kata** in the palette, or `F9`, opens a right split in the focused Pane's directory. A literal `kata://<project>/<short_id>` link focuses a running kata Pane and selects the Issue without restarting it, or opens a split with `tern-kata --issue <project>/<short_id>`. `https://kata.invalid/<project>/<short_id>` does the same: Tern's chat Markdown (`md` nodes, as OMP sends) links `https` hrefs but draws `kata://` as plain text, and `.invalid` never resolves, so without the plugin the link opens a dead page. Links may select closed or other-Project Issues in detail without changing the current Collection. Percent-encoded segments, query strings and fragments are declined. Missing `tern-kata` on the Pane's `PATH` prints `go install github.com/Dangerboi/tern-kata@latest` in the Pane. OS scheme registration is separate; the plugin handles links delivered inside Tern.

The plugin sends a TSP `action` to `main.columns.list.issues` with `act: "select-issue"` and `value: "<project>/<short_id>"`. The binary uses the same model message path for startup selection and this action; its terminal title `tern-kata` lets a reloaded window plugin discover an existing Pane.

Tern 0.6.2 (`4b3ed42`) performs synchronous login-environment capture when a plugin uses `Launch.command`. A minimal hook containing only `cx.layout:split(cx.session:focused(), "right", {command = "exec /bin/sh"})` reproduced a 57.95 ms capture, the warning `plugin="bare-split" hook="command open" error=runtime error: tern: command open exceeded 50 ms`, and a skipped second launch: the Pane count stayed at two. The shipped Launch fields and runtime preferences expose no per-launch capture switch.

The launcher instead opens a default shell split in the target's directory and checks `PATH` directly in that Pane with `cx:run`, executing `tern-kata` or printing the install hint. It uses neither a timer nor `Launch.command`. A minimal split-plus-run hook produced its output on two consecutive launches without reload, in distinct Panes. The plugin smoke attempts consecutive palette/key launches without reloading and rejects hook-budget warnings; real OSC-8 links also open and reuse a Pane in that same plugin session.

Closing a Pane that runs tern-kata does not touch tern-kata until the user confirms: Tern's window raises its "a program is running" prompt itself (its debug log shows `view operation requested kind="close_pane"` and the dialog in the same millisecond), so the program cannot delay it. Measured in a headless Tern, in a real window attached to its session daemon, and in a window attached to a host over a real Tern remote link (QUIC, `tern remote serve`, relayed through a UDP proxy that added 80 ms of round trip and capped the link at 250 KB/s), the prompt took about 10 ms for tern-kata, `kata tui` and `vim` alike: with the live stream open or reconnecting, with the daemon unreachable, while the 607 KB first frame of a 1455-Issue Project was still crossing the link, and with a 3 s one-way delay at 20 KB/s (19 ms). During a storm of Issues reordering the list it rose to 30-40 ms, locally and over the link. Once the user confirms, Tern closes the Pane's terminal and tern-kata ends in about 55 ms, leaving no process (`kata tui` ends in about 10 ms): the difference is the Tern SDK's 50 ms drain in `Session.Close`, which `q` pays too. A cancelled prompt changes nothing in tern-kata. A pause of seconds before the prompt was not reproduced in any of these, so it comes neither from tern-kata's shutdown nor from its output on the link.

The Issue list is ordered by last update, most recently updated first, at every hierarchy level (children under a parent included) and inside every Collection group; ties break by UID so the order is stable. Deadlines' Overdue and Today groups keep deadline-date order first. When live updates reorder the list, the selection stays on the same Issue.

Selecting an Issue loads its detail beside the list: the title as `#<short_id> - <title>` (the id in the theme accent) with the status badge on its own line under it (`open`, or `closed · <reason>` for a closed Issue with a close reason), then the properties as one `Name:` grid, names lined up in one column and values in the next, in the order Author, Created, Updated (both in the Events rows' `2026-10-09 22:42` local time), Scheduled and Deadline when set, Owner (`Unassigned` when nobody owns it), Priority (a theme-toned badge), Labels (chips), Parent (the reference as a link with the parent's title), `Children: N open / M total` on a parent. Rows with no value are left out, and there is no Revision or Project row. Then the Markdown body (without a heading). On a child, a leading `## Parent` section that names the parent (as a whole word: `vsmf`, `#vsmf` or `project#vsmf`) is not drawn, and a body that is only that section reads `No body yet.` (the `Parent:` row shows it); the body editor still opens the full stored body. A parent's children are not listed in the properties: the counts are the daemon's own, the same as the list's kids cell, and an Issue without children shows no counts line, and neither does a parent the Project's counts request did not cover (a parent in another Project, reached by a link jump, still shows its Children table), because the plugin makes no extra daemon request for it. Under the body a bold **Children** heading starts a table with one row per child (the reference in the same short form as Links rows, the status, the title and the time since its update; a closed child's status, title and time muted; the reference, status and time cells are padded to their widest value and never wrap, so the columns line up, and the title takes the rest of the row and ends in an ellipsis when cut), in the list's order, most recently updated first. A child not loaded in the current Collection is still listed, by its reference alone, and nothing new is fetched for it. A click on any cell of a row opens that child, and the table is left out when the Issue has no children. Under the table an **Activity** heading shows three tabs, `Comments (N)`, `Events (N)` and `Links (N)`: only the active tab's rows are drawn, the active name is accent and bracketed (`[ Events (3) ]`), an empty tab says so (`No comments.`), and a comment reads `dana / 2026-10-08 20:05`, the author and the time in the Events rows' format and local zone, with the body below. The active tab stays when another Issue opens. Status is `accent` when open and `muted` when closed; priority is `error` (P0), `warning` (P1), `info` (P2) or `muted`. Quick field edits (`+`, `-`, `a`, `A`, `!`) refresh the block in place. `enter` opens detail, `esc` or `←` returns to the list (then the Menu, or the Menu sidebar in an unbound directory), `tab`/`shift+tab` cycle the Activity tabs (a click on a tab name selects it), `j`/`k` move the row cursor through the child rows first and then the active tab's rows, and `enter` opens the selected child or follows the selected row's referenced Issue; `esc` unwinds those jumps (a new tab puts the cursor on its first Activity row). `L` hides or restores detail; the detail has no Back or Hide detail buttons, `esc` and `L` do both. The detail is one scroll container (title, properties, body, Children, then the Activity tabs), not a list of items: with it focused, the wheel, `↓`/`↑` (a line) and `pgdn`/`pgup` (a page) scroll it and `j`/`k` move the row cursor. The detail never asks Tern to reveal a node: Tern keeps the last revealed node in view and refuses to scroll the wheel past it, so one reveal froze the wheel until the node was removed. So `tab` and `j`/`k` move the cursor without scrolling to it (probed for 6v5n: a nested row list with a reveal after each `j`/`k` scrolled the whole detail to its end and then left the wheel dead both ways, so the rows stay un-revealed); a cursor row off screen is reached with `↓`/`pgdn`. The detail column scrolls back to its top whenever a different Issue replaces the shown one, whichever column has the keys; a refresh of the same Issue leaves it where it is.

The layout follows the Pane's width, as kata's own TUI does. From 140 columns the Issue list and detail sit side by side, each in its own bordered panel (a Tern card); the panel with the keys has the accent ring and the other the muted tone, and they swap as focus moves (with the Menu sidebar too in an unbound directory while a fixed Collection is current, which has no border). The top bar sits above the columns at every width from 80, outside the borders. From 80 to 139 columns only one column shows, with no border: the Issue list, or detail once it has the keys, or the sidebar when it has them in an unbound directory on a fixed Collection. Below 80 columns one centred notice asks to widen the Pane to 80 columns, with no footer or layers drawn over it, and `q`/`ctrl+c` still quit. Width never changes the model (`ResizeMsg` only records the columns), so widening again brings back the same Collection, selection, open detail and layers. The window plugin's **Open kata** splits the focused Pane, so in a window under 160 columns the new Pane is under 80 columns and shows the notice.

Issue rows read like kata's TUI: every other drawn row (the first bare, the second shaded, and so on; the header never) carries the role `tern-kata.stripe`, and a style sheet the plugin installs on its surface gives that role a background of the theme's own text colour at 5% opacity, so it is a light tint on a dark theme and a dark one on a light theme and follows either. Position among the drawn rows decides, so the stripes stay alternating after a fold, a filter, a Collection switch, the flat toggle or a live reorder, at every width. The selected row is painted in the theme's accent fill (`var(--accent-fill)`) with white text on every span, closed Issues' muted text included (about 4.8:1 against the smoke theme's accent, checked in `16-qm89-accent`), and wins over the shade and the hover; only the Issue list is touched. Tern confines the sheet to this Pane. Rows show no labels: they stay in the detail properties, the label filters and label editing. The same sheet hides the `insert` chip Tern draws at the end of every single-line input (each sets a mode so Tern's native editing stays off and the model handles the keys, so typing is unchanged) and gives ordered lists in every markdown node (body, comments, conflict prompt) 40px of start padding so numbers of two digits draw whole; bullet lists are untouched. Tern's own list rule needs `!important` to lose, and its CSS has no `ch` unit and no `padding-inline-start`.

The app never asks Tern to scroll a column the view isn't drawing: Tern answers a scroll of an unknown node with an `unknown id` error event, which ends the program, and that was the crash in narrow Panes. Whenever a different Issue's detail arrived the model asked the detail column to return to its top; with one column showing and the list in it, `j` (then the daemon's answer) sent that scroll to a detail the view had not drawn, and the Pane exited. Page Up/Page Down did the same below 80 columns, while the first load or a daemon failure filled the Pane. The model only asks for scrolls and reveals as intents; the Pane driver (`driver.Step`, one pure step from a Tern input or daemon result to the next state, the view, the Tern ops and the daemon commands) alone decides which focus, reveal and scroll ops go out, and drops a scroll of a column that isn't on screen and a tab reveal while the Activity tabs aren't drawn; a column drawn again starts at its top anyway. The driver's tests feed it Tern inputs and daemon results and assert the ordered ops, so none of this needs a live Tern.

Each Comment and each Event is its own bare card in the Activity section: the head has the author (strong) and the time (muted, in your local zone, `2026-10-08 20:05`) as separate spans and the body sits below it, and the `j`/`k` cursor marks the whole card. Links rows and the `No comments.`/`No events.` empty states are unchanged. An Event's body reads as one sentence, newest first (the author is in the head): `assigned to alice`, `closed: done` with the whole close message and evidence (commit, PR, test command) wrapped below, `` added label `bug` ``, `set priority to 1`, `edited title and body` with the new title below, and `commented` with the whole comment, and so on for created, commented, unassigned, reopened, unlabelled, priority cleared, linked, unlinked, scheduled, deadline and moved events. The verb carries a Tern tone: created accent, closed success, reopened warning, the rest neutral. An event type kata adds later shows as sorted `key: value` pairs; values are shown whole. Issue references in Links rows and in Events that name another Issue render as links: the id in the accent tone, underlined, carrying the jump click, with the relation and the actor muted, and a Links row reads `parent | #aw8e - Spec: tern-kata milestone 2, browsing polish`: the relation and ` | ` muted, the id a link (`#<short_id>` in the shown Issue's Project, `<project>#<short_id>` otherwise), and ` - ` and the Issue's title, clickable, only when that Issue is loaded, with the spaces drawn as written (Tern collapses each text node's edge spaces in layout, so the row's pieces carry them as no-break spaces: `parent |` + NBSP, then the reference, then NBSP `-` NBSP, then the title); the Parent property of the detail's grid draws the same reference, ` - ` and title without the relation lead; rows without a reference stay plain and there is no separate button. The model builds these sentences from the event type and its decoded payload (`model/history.go`); the view only styles them. `07-n988-history` checks a readable assigned/closed/reopened history against a throwaway daemon.

Loading never blanks the Pane: only the very first load shows a full-Pane message. Later, switching Collection keeps the previous list under a muted `loading…` marker in the top bar title, and selecting another Issue keeps the previous detail under the same marker in its heading, until the new content replaces it in place. Element keys are fixed per Issue, Activity tab and row, so Tern keeps native scroll. Clicking an Issue row does not reveal or scroll the list. A refresh of the same Issue leaves the reader where they were; a different Issue opens at its top through the scroll op (never a reveal). Tern keeps the node of the last reveal in view and ignores the wheel past it until that node is removed, so the detail never reveals: not for clicks, not for keys, and the wheel keeps scrolling whatever was clicked or pressed.

Selecting a parent Issue never blanks the Pane, by `j`/`k`/arrows or a click, collapsed or expanded, however many children it has. A parent's detail carries one Children row and one Link row per child, and its history, so it is far taller than the Pane. Tern's `row` centres its children unless told otherwise, so the columns row used to centre the shorter list column against that tall detail and carry it out of view, leaving only the detail; moving to a short Issue brought the list back. The columns now align to the top and the list stays put beside the detail.

Page Up/Page Down scroll the Menu sidebar by a native Tern page, and move the Issue list selection by ten rows, clamped at the ends, while the nearest reveal keeps it in view; in the detail they scroll its viewport by a page, and `↓`/`↑` by a line (the page-by-ten-rows workaround stays in the Issue list only); in search they enter the results before moving. Footer hints are clickable and use the same keymap dispatch as their displayed keys. Form hints only show bindings handled by that form. Link labels describe the relation from the selected Issue: incoming parent links show children, and incoming blocking links show `blocked_by`.

Press `e` to edit the selected Issue body, or `c` in detail to add a comment. The native editor keeps UTF-16 caret/selection offsets and an application undo stack (`ctrl+z`); `ctrl+o` saves. Non-empty Drafts ask before `esc` discards them. Drafts are keyed by Issue UID and keep their original revision through live refreshes. Revision conflicts show your Draft beside the current body: `o` retries against that version, and `d` discards only your Draft. Saves fetch and compare the Issue revision first: kata v0.18.0 ignores body PATCH `If-Match`, so the check-then-write race remains until upstream enforces it.

`ctrl+e` opens the Draft in `$EDITOR` via a private temporary Markdown file. The app stops its input reader and closes the Tern Session (restoring tty/raw mode), runs the editor with the real stdin/stdout/stderr, then reconnects and restores the in-memory Draft. `Suspend` alone is not sufficient because it does not release stdin. Successful external edits return to the Draft, not directly to kata; use `ctrl+o` to save. Editor errors keep the original Draft.

Tern 0.6.2's Linux headless runner sends `meta+o`, `meta+e`, and `meta+z` for the corresponding `Ctrl` harness chords. Both the intended `ctrl` and observed `meta` variants are bindings; the headless smoke exercises the actual Tern mapping. Desktop modifier mapping is not independently verified.
In the list or detail, `+` adds a label, `-` removes one, `a` assigns an owner, `A` clears the owner, and `!` sets priority. Prompts save with `enter` (or `ctrl+o`/`ctrl+s`) and cancel with `esc`; priority accepts 0-4 or `-` to clear. Labels complete with up/down and tab using project labels for addition and attached labels for removal. Rejected writes keep the prompt and kata's error visible. Writes use `--as <actor>`, then `KATA_AUTHOR`, `USER`, git user.name, or anonymous, in that order; authenticated kata identities retain authority over the requested actor.

`n` opens a create Draft; `N` creates a child of the selected Issue with its parent link included in the create request. Tab/shift+tab moves through title, native body editor, comma-separated labels, owner and priority (0-4). Only Title is required; the other fields' labels end in `(optional)`. Up/down chooses a label suggestion and ctrl+space completes it. Ctrl+o creates; Escape confirms discard for non-empty Drafts. Project Collections create in that Project; other Collections use the selected Issue's Project, or the bound Project if nothing is selected. Child creation always uses its parent's Project. Without either Project, creation reports an error. Rejections retain the Draft and kata's error. The returned UID stays selected through refresh, and the parent expands to expose a created child.
If a created Issue is excluded from the current Collection, its pending selection ends when you explicitly navigate or select another Issue or Collection.
The Pane opens with a top bar above the columns and outside their borders, a node of its own (`main.topbar`, drawn at every width from 80 columns, in the single-column detail and sidebar views too) of one row: the title alone in the left cell (`Project: <name>` in a Project, else the Collection title, with the loading marker; clicking it opens the Menu), `open: N · closed: N · all: N` (the Project's catalog stats for a Project Collection, bound or picked, which no filter narrows; for any other Collection counts over the Issues it lists, which the status, search, owner and label filters have already narrowed, because the daemon snapshot carries stats for Projects only) in the middle, and on the right `Daemon: local|remote · kata <version>` as read at discovery, then ` · ` and a `Menu` button in the accent tone (click `key=p`, so a click is the key, and `p` still opens it; it never shrinks), all refreshed live. When the row is too narrow, Tern's flex truncates the Daemon first, then the counts; the title and the button stay whole; the model does no width arithmetic. A second line, `main.filters`, lists the active filters (`status=open · owner=x`) and exists only while a filter is on.
The top bar and the header row stay pinned: only the Issue rows scroll, in a scrolling list of their own, and the detail scrolls as one container, a Tern list with a single child that holds the title, properties, body, Children and Activity (`main.columns.detail.viewport`, child `.content`); the columns fill the Pane under the bar and clip to it, so the Pane itself never scrolls (an uncapped list grows to its content and Tern then scrolls the whole Pane, bar included). Where a column has no border the list fills the column exactly; inside the side-by-side cards Tern gives a card body no fill, so the list is capped at 0.6 of the window height and the bar stays pinned from windows about 600px tall up, below which a card clips its lowest rows. Tern's scroll op reaches a list's scroller only through a node inside it, which is how the detail scrolls (`scroll` aimed at `main.columns.detail.viewport.content`, by `line-down`, `page-down` and `start`); the Issue list's rows are many items, so Page Up/Page Down move the selection by a fixed ten rows instead (Tern reports no Pane rows); the wheel, `j`/`k` and `tab` scroll too. Switching Activity tab, by `tab`/`shift+tab` or a click on a tab name, brings the new tab into view: the app reveals, inside the detail scroller and with `nearest`, the last node of the active tab's rows (or its `No …` line), then the tab names row. So a reader at the bottom of the detail sees a longer tab's rows without scrolling, a short tab that already shows leaves the detail where it is, and a tab taller than the detail ends with the tab names at the top. Nothing is sent when the tab stays (a click on the active tab) or while the detail is not drawn (folded away by width, still loading, failed), since Tern ends the program on a reveal aimed at a node it does not draw; a reveal that arrives after a faster tab press has replaced its row is rejected by Tern and ignored. Opening a different Issue still scrolls the detail to its start. `j`/`k` and the arrows reveal the selected row with `nearest`, the least movement, and never move the bar. Under the top bar a header row (`#`, prio, status, title, kids, owner, updated; its own node, `main.columns.list.header`) labels the columns. Issue rows show short id, priority, status, title, kids (the daemon's open/total direct children whatever the filters, blank when none), owner, relative updated time (`2h ago`, `3d ago`) and labels; `owner` appears only when the list has the full Pane width and is dropped, from header and rows, when the list shares the Pane with detail. Cells have fixed widths (`#` as wide as the longest id with its tree indent, prio 4, status 6, kids 5, owner 8 with an ellipsis, updated 8; a blank cell keeps its width) so they line up with the header, and the title takes the rest of the row and is cut with an ellipsis. Date/Project group headings are bold, and the top bar title is accent while the list has focus. Nested lists start collapsed: `space` toggles the selected parent's children, `→`/`←` expands/collapses, `E` toggles every parent, and `v` switches flat/nested (returning to nested collapses all). Expansion follows Issue UIDs across refreshes; collapsing moves a hidden selection to its nearest visible ancestor. Colour comes only from the host theme's tones: open status is accent and closed muted (the whole row too), priority is P0 error, P1 warning, P2 info and P3–4 muted, each label is its own mark-styled chip, and the selected row uses the accent tone.
A click takes the same state change as the keys that reach the same place, from any column. A row click gives the list the keys with that row selected; on a parent row it also expands or collapses the children, even from the sidebar or detail. A Collection click (a sidebar item in an unbound directory, a picker row in a bound one) switches as `enter` does, a click on an Activity tab name or a row gives detail the keys on that tab, and a reference link jumps as `enter` does. So `esc` backs out the same way after a click as after the keys: each jump unwinds one Issue, and jump history belongs to the detail column, so leaving it by any key or click (a row, a Collection, the top bar title) ends it and `esc` never replays an earlier jump. Clicks inside a layer (filters, create, close, the label prompt, help, search) leave `esc` closing that layer. A click on a field of the Create, Close or Filters card makes it the field the keys edit, as `tab` does. Click actions are defined once in `view/actions.go` beside the node ids, which both encodes them for the view and decodes them for the Pane driver.
A double click on an Issue row, a parent's or a nested child's included, opens it from any column or mode, as selecting the row and pressing `enter` does: side by side the keys move to the detail, and in the single-column tier the detail replaces the list, so `esc` backs out as after `enter`. Every Issue row carries a `dblclick` action naming its UID (`open-row=<uid>`). In a headless Pane Tern delivers a double click as the row's two single clicks (a leaf's `select` twice, a parent's `toggle-expansion` twice) and then that action, so a parent's two folds cancel and its fold ends where it began, and a single click keeps its meaning. Without the action Tern sends a list `activate` event instead (for a parent, before its two folds); the plugin does not use it.
In the list, `tab` moves to the detail when the list and detail are side by side (from 140 columns) and an Issue is selected, as in kata's TUI; with one column showing, or no detail, it does nothing, and `enter` still opens the detail. The footer shows `tab detail` only when it applies. In the detail `tab`/`shift+tab` still cycle the Activity tabs, and `tab` in the sidebar does nothing.
Every editing card ends in a row of buttons labelled with the action and its key, the primary one in the accent tone: Create Issue (`Create Issue (ctrl+o)`, `Create child Issue (ctrl+o)` for a child, then `Cancel (esc)`), the label/owner/priority form (`Save (enter)`, `Cancel (esc)`), New Project (`Create Project (enter)`, `Cancel (esc)`), the body and comment Draft editor (`Save (ctrl+o)`, `$EDITOR (ctrl+e)`, `Discard (esc)`), Close Issue (`Close Issue (ctrl+o)`, `Quick done (ctrl+d)`, `Cancel (esc)`, after its note on Quick done), the Draft conflict card (`Overwrite (o)`, `Discard Draft (d)`) and Filters (`Apply filters`, `Cancel`). The discard prompt of a Create or Draft card has `Discard (y)` and `Keep editing (n / esc)`, the safe choice in the accent tone. Every button's click is the footer-hint `key=<chord>` route, so a click is the key, validation errors included. The buttons are left out while the card is saving, and the footer hints stay.
Collections (Inbox, Today, Upcoming, Deadlines, All Open, Logbook and every Project) load from the daemon UI snapshot. The sidebar shows only in an unbound directory while a fixed Collection (not a Project) is current; entering a Project, picked or just created through New Project (bound or not), hides it, and picking a fixed Collection again from the Menu brings it back. Whenever the sidebar is hidden (a bound directory, or an unbound one inside a Project), `p`, a click on the top bar title, or `esc` from the Issue list opens the **Menu**, a popup inside the Pane listing the fixed Collections with the bound Project pinned first, then **Projects** and **New Project**, and the current Collection marked `current`. The Menu never lists the kata Projects inline: `enter` or a click on `Projects` opens a second level with a `Back` entry and every Project (the current one marked and under the cursor), and `esc` or `Back` returns to the top level (a second `esc` closes the Menu). The sidebar has the same two levels, and returns to its top level once any Collection is entered, from the sidebar or the popup. Typing filters titles in any case, across both levels at once (a Project's name is found without entering `Projects`), and `esc` with a filter closes the Menu. `↓`/`↑`/`home`/`end` move, and `j`/`k` move while the filter is empty and are typed once it has text; `enter` or a click switches, and `esc` or the popup's `Close (esc)` button closes the Menu without changing anything (on the Projects level the button reads `Back (esc)` and goes back, like `esc`). After a switch the top bar title names the new Collection and the bound Project is the Menu's first entry. Unbound directories open Inbox with the sidebar as a third column: press `esc` from the Issue list to focus it, navigate with `j`/`k`/`↓`/`↑` or `g`/`G`/`home`/`end`, and press `enter` to switch, or `p` to open the Menu (a click on the top bar title does the same); sidebar items are also clickable. Date headings match kata's web UI: literal calendar dates for Upcoming and Logbook, Overdue/Today for due work, with today's evening Issues merged into Today. Snapshot requests include the local calendar date and IANA time zone and reuse ETags only for the same Collection intent.

**New Project** is the last row of the unbound sidebar's top level and the last entry of the Menu's top level. It opens a form with one field, the name, starting with the directory's base name: `enter` (or `ctrl+o`/`ctrl+s`) creates, `esc` cancels and returns to where the form was opened (the picker keeps its filter), and the footer hints are clickable. In an unbound directory it binds the directory as `kata init --project` does: the daemon creates the Project, or returns the active one of that name, and tern-kata then writes `.kata.toml` and a `.kata.local.toml` line in `.gitignore` where kata would (the workspace root, else the Git root, else the directory) instead of asking the daemon to, so the daemon never needs to see the directory. A `.kata.toml` that already names another Project is refused before the daemon is asked; use its name. The Pane then switches to that Project without the sidebar, and the next start finds the binding. In a bound directory the picker's New Project only creates the Project, as `kata projects create` does, and switches to it; the directory and the pinned picker entry stay on the bound Project. In a bound directory a name that is already taken is a rejection too, as `kata projects create` reports it; binding an unbound directory to an existing Project by name is kata init behaviour and stays. A rejection, such as a taken name or the name of an archived Project, shows kata's message in the form and keeps the name; editing the name clears the message. While the daemon is unreachable the form refuses to submit.

`/` searches the current Collection through the daemon snapshot as you type. Up/down moves through live results; `enter` first focuses results and then commits the search. In results, `esc` or `/` returns to the query; query `esc` restores the previous search and selected Issue. Every Collection starts with the status filter on all (open and closed Issues, no heading suffix) and keeps it across live refreshes; `s` cycles all → open → closed → all, and the filter form starts on the current status. `f` opens Project, status, owner, label and relationship filters: tab/shift+tab changes fields, left/right or space cycles choices, and ctrl+o (or ctrl+s) applies; Escape cancels. Owner matches exactly, comma-separated labels match any label, and relationships are Has parent, Has child, Blocks, Blocked by or Related. All axes combine, remain visible in the list header, and survive event refreshes and Collection changes. Project filters cannot widen a Project Collection. `c` clears every filter and restores the Collection's default status; explicit all status includes both open and closed results. The form also has Apply filters and Cancel buttons.

A search that is an Issue id lists that Issue alone. A query counts as an id when it is a kata short id (4 to 26 characters of its lowercase base-32 alphabet), bare or with a leading `#`, in any case. The model resolves it through the open-issue lookup that `--issue <project>/<short_id>` and `kata://` links use, in the Collection's Project (for a Collection that is not a Project, the Project filter's, else the bound Project), then reads the Collection without the query text and keeps that Issue only when the Collection lists it. A query that is not an id, an id the Project does not have, and an id outside the Collection all run kata's full-text search as before, and so does a query typed past an id (`0zpn link`). The lookup shares the snapshot queries' one-request-at-a-time coalescing, so a slow lookup never replaces a newer query's results, and live refreshes, `enter`, `esc`, result navigation and Collection changes treat an id result like any other search result. It makes no new kind of daemon request (ADR-0001).

Press `x` in the Issue list or detail to open the close form. Each field has its name above it (`Reason`, `Message`, `Commit SHA (optional)`, `PR URL (optional)`, `Test command (optional)`, `Issue reference (duplicate / superseded)`, `Rationale (audit-no-change)`). Use `tab`/`shift+tab` to select a field, `ctrl+u` to clear it, `ctrl+o` to submit, or `esc` to cancel. Commit SHA, PR URL and test command evidence are optional fields, but normal `done` requires at least one; duplicate/superseded and audit reasons have dedicated reference/rationale fields. **Quick done** (`ctrl+d`) sends the owner-local interactive exemption, not fabricated evidence. The daemon still enforces parent-close and throttle guards. Close uses the loaded revision and `close-v1`; conflict, guard and throttle messages remain readable in the form. Press `r` to reopen.
